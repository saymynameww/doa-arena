本文档说明每个页面**有什么、怎么交互、对应哪条需求**。原型是中等保真：布局、控件、文字、交互流程接近真实界面，配色和细节以 Ant Design 默认风格为准，不追求最终视觉效果。原型中的数据全是假数据。

**原型与正式实现的关系：**
- 原型用手写的参数声明表示算法参数；正式界面中，算法、阵列、误差的参数表单**全部由后端 JSON Schema 自动生成**（架构 7.2 节），前端不写任何算法专用代码。原型中的参数只是“生成后长什么样”的示例。
- 原型中的校验、能力检查、指标数值都写在页面脚本里；正式界面中它们全部来自后端（配置校验接口、插件的 `check()`、结果文件），前端不做任何计算。
- 原型用 SVG 手绘曲线；正式界面使用后端返回的 Plotly 图表（架构 ADR-05）。
- 原型中的“运行”是定时器模拟；正式界面通过 SSE 接收进度（架构 6.3 节）。
- 原型中凡是提示“原型演示”的操作（导出、重新运行、切换工作目录等）都没有真正执行。结果页顶部的“原型演示”一行用来切换三种实验方式的结果页，正式界面没有这一行。
- 页面右上角的“显示需求编号”开关只属于原型，用来在评审时对照需求条目。

## 1. 全局布局与通用规则

### 1.1 布局

| 区域 | 内容 |

| 右侧主区 | 当前页面 |

导航结构：

| 分组 | 入口 | 说明 |
|---|---|---|
| — | 工作目录切换器 | 显示当前工作目录，点击后列出已登记的工作目录和“管理工作目录”（FR-DAT-01b） |
| 实验 | 新建实验、历史实验 | — |
| 资源 | 算法库、模板 | — |

“运行与结果”和“多实验对比”不是导航入口：前者在运行实验后自动进入，或从历史实验点开；后者从历史实验勾选后进入。两个页面顶部都有返回历史实验的路径，导航中“历史实验”保持高亮。

页面与路由（与架构 7.1 节一致，路由没有变化）：

| 路由 | 页面 | 章节 |
|---|---|---|
| `/`（原型中为 `#config`） | 新建实验（实验配置） | 2 |
| `/runs/:id`（`#run`） | 运行与结果 | 3 |
| `/history` | 历史实验 | 4 |
| `/compare` | 多实验对比 | 5 |
| `/algorithms` | 算法库 | 6 |
| `/templates` | 模板 | 7 |
| `/leaderboard` | 排行榜（P1） | 8 |
| `/settings` | 设置 | 9 |

最小支持宽度 1024 px（窗口宽度）。实验配置页在主区较窄时由三栏变为两栏，预览和摘要移到算法列下方。

### 1.2 通用规则

这些规则对所有页面有效，是这一版设计的出发点。

| 规则 | 内容 |
|---|---|
| 主次 | 每个页面只有一个主要操作用实心按钮；次要操作收进菜单（“⋯”、“导出图”、“导出数据与报告”） |
| 警告和错误 | 显示在出问题的对象旁边（字段下方、算法卡片上、结果页顶部），并说明怎么改；不单独放在页面末尾 |
| 置灰必须给原因 | 不能选、不能点的东西，原因直接写在旁边，不依赖悬停 |
| 算法的视觉身份 | 每个算法实例同时用颜色、线型、标记三种方式区分，黑白打印也能分辨。同一个实验中，配置页的卡片、图例、表格、提示框使用同一组样式。CRB、真值等参考线统一用黑色虚线、不带标记 |
| 一句话摘要 | 折叠的分组、收起的算法卡片、结果页的实验条件、模板列表都用一句话概括内容，不需要展开就能知道里面是什么 |
| 可复现信息 | 种子、代码 commit、未提交修改、信号模型版本、模型包哈希在结果页可以直接查到（NFR-14） |
| 空状态 | 没有数据时说明原因和下一步怎么做 |
| 删除 | 需要确认，对话框写明文件去向（移入 `.trash/`） |

算法样式（颜色、线型、标记的序列）由核心库的图表模块定义，前端通过接口取得，保证网页上的图和导出的图一致。具体分配规则属于实现细节，要求是同一个实验内各处一致。

### 2.1 实验方式

| 元素 | 行为 | 需求 |
|---|---|---|
| 三张卡片 | 单次实验、蒙特卡罗、参数扫描，每张带一句说明（做什么、看什么）。这是进入页面后的第一个决定，选定后页面只显示相关设置 | FR-EXP-01 |
| 扫描变量 | 只在“参数扫描”时显示。显示当前扫描的字段和取值范围，点击跳到该字段；还没有选择时显示红色提示 | FR-EXP-03 |
| 试验次数 | “参数扫描”时标签为“每点试验次数”，“蒙特卡罗”时为“试验次数”，“单次实验”时不显示 | 数据格式 3.6 |
| 指标 | 可逐个开关：RMSE、成功率、分辨概率、耗时、CRB 参考线；旁边是成功门限。“单次实验”时不显示，改为一句说明（结果页显示空间谱和估计角度）。指标列表来自已注册的指标插件 | 数据格式 3.7 |

### 2.2 场景

| 元素 | 行为 | 需求 |
|---|---|---|
| 分组 | 阵列、信源、阵列误差、高级，可折叠；折叠后标题旁显示一句话摘要。字段由所选阵列插件、误差插件的 Schema 生成 | FR-SCN-01~08、12 |
| 信源数 K | “固定 / 随机”；随机时输入取值集合 | FR-SCN-03 |
| 角度 | 下拉切换“固定角度 / 范围内随机 / 中心 ± 间隔/2”，切换后只显示对应输入项 | FR-SCN-04，数据格式 3.3 |
| 相关性 | 选“部分相关”时出现幅度和相位两个输入框 | FR-SCN-06 |
| 阵列误差 | 四类各占一行：开关、名称、一句说明。打开后显示实现方式（固定 / 每次随机）和参数；关闭的不展开 | FR-SCN-07、08 |
| 高级 | 随机种子（“换一个”随机生成）；“参数扫描”时还有公共随机数开关 | FR-SCN-09，数据格式 3.6 |
| 即时校验 | 输入时按 300 ms 防抖调用后端校验。错误（红色）和警告（黄色）显示在字段下方，并写明怎么改，例如“信源数 K 必须小于阵元数 M（当前 K = 16，M = 16）” | NFR-31，数据格式 3.9 |

### 2.3 扫描变量就地绑定

选择“参数扫描”后，每个可以扫描的数值字段右侧出现“扫描”。

| 行为 | 说明 |
|---|---|
| 点击“扫描” | 该字段高亮，输入框由单个值变为取值范围，按钮变为“取消扫描”。同一时间只有一个扫描变量，点另一个字段的“扫描”即切换 |
| 取值写法 | `起:步长:止`（如 `−10:5:20`）或逗号分隔的列表。输入框下方即时显示解析结果，如“7 个取值：−10，−5，0，5，10，15，20”；无法识别时提示写法 |
| 哪些字段可以扫描 | 由配置路径规则决定：任何单一数值字段（数据格式 3.6、3.8 节），包括场景参数、误差参数和算法实例的参数。前端只看字段类型，不需要知道具体参数 |
| 算法参数 | 展开算法卡片后，数值参数同样有“扫描”，只改变这一个算法实例 |
| 字段不再有效时 | 扫描的字段被隐藏或所属误差被关闭后，扫描变量视为未选择，运行前给出错误 |

需求：FR-EXP-03，数据格式 3.6、3.8 节。

### 2.4 算法

| 元素 | 行为 | 需求 |
|---|---|---|
| 算法卡片（收起） | 默认收起，占两行：样式色块、可编辑的显示名、“外部”标签、复制一份、移除、启用开关、展开；第二行是参数摘要，只列出**与默认值不同的参数**，全部为默认值时显示“默认参数”。这条规则对所有算法通用 | FR-ALG-02、03 |
| 算法卡片（展开） | 点卡片展开：一行来源信息（插件 id、来源、版本、commit、是否有未提交修改），然后是由 Schema 生成的参数表单；声明为 `advanced` 的参数收在“高级”里 | FR-ALG-01c、02，接口规范第 5 章 |
| 提示 | 贴在卡片上。黄色：插件 `check()` 的警告（如相干信源未平滑）、训练范围。红色：不能运行的原因（没有选模型包、模型与阵列不匹配、能力不满足），卡片边框变红 | FR-ALG-05、06，FR-GEN-06 |
| 复制一份 | 在下方生成同一算法的另一个实例并展开，用来比较不同参数（如平滑开 / 关） | FR-ALG-03 |
| 启用开关 | 停用的实例保留在列表中，变淡，不参与运行和次数估计 | 数据格式 3.5 |
| 添加算法 | 弹出面板：搜索框；按“内置基线 / 外部，来自某目录”分组；每项显示名称、适用条件、一句简介。当前场景下不能用的算法置灰，简介位置改为原因 | FR-ALG-01、05 |
| 显示名 | 即图例中的名字。同一实验中必须唯一（数据格式 3.9 节），重复时由后端校验给出错误 | FR-ALG-03 |

已经加入的算法在场景改变后不再适用时，不从列表中移走，而是在卡片上给出红色提示并阻止运行，由用户决定停用它还是改场景。

### 2.5 预览、摘要和运行栏

| 元素 | 行为 | 需求 |
|---|---|---|
| 场景预览 | 常驻在右侧。半圆角度刻度（−90° 到 90°）、信源方向、阵元位置；故障阵元为红色；有位置误差时阵元偏移（示意）；角度随机时画出取值扇区。下方一句文字说明。参数改变后即时重绘 | FR-SCN-11 |
| 配置摘要 | 常驻在预览下方，六行：实验方式、阵列、信源、阵列误差、算法、随机种子。用于运行前最后核对 | — |
| 运行栏 | 吸附在窗口底部，滚动时始终可见 | — |
| 运行次数估计 | “7 个扫描点 × 500 次试验 × 4 个算法，共 14,000 次估计，预计约 40 秒”；超过阈值时变为黄色并建议先用少量试验确认配置 | FR-EXP-04 |
| 问题汇总 | 有错误或警告时显示“1 个错误，2 条警告”；点击列出全部，每条标明对象，点一条跳到对应字段或卡片并闪烁提示 | 数据格式 3.9 |
| 运行实验 | 有错误时禁用，旁边说明“改正错误后才能运行”；只有警告时可以运行。提交后进入运行与结果页 | FR-EXP-05、NFR-31 |

标题栏：实验名称；“从模板加载”列出全部模板（第 7 节）；“保存为模板”；“导出 JSON / 脚本”下载当前配置或等价的 Python 脚本（FR-SCN-10、FR-API-06）。

编辑中的配置自动保存到浏览器本地存储，刷新页面不丢失（架构 7.3 节）。

## 3. 运行与结果页

同一页面按实验状态切换内容（架构 7.1 节）。页面从上到下的顺序是：先说明这个结果能不能信，再给出结论，最后是细节。

```
历史实验 / 实验结果
相干信源 SNR 扫描 [完成]                [复制并修改] [重新运行] [导出数据与报告]
实验 ID …，在网页上运行，10-29 14:30 开始，用时 42 秒
┌ 进度（只在运行中显示）──────────────────────────────────────────────────────┐
├ 警告与错误：每条标明算法 ───────────────────────────────────────────────────┤
├ 实验条件：一句话概括                [有算法的代码未提交]  [查看复现信息]    ┤
├──────────── 主图 ────────────────────────────────────┬── 备注与标签 ───────┤
│ RMSE 与 CRB | 成功率 | 分辨概率 | 耗时   对数纵轴 样式 导出图 │              │
│ 图例（点击显隐）                                      │                     │
│ 曲线；悬停显示各算法数值；点击扫描点                  │                     │
├──────────── 指标汇总 ────────────────────────────────┤                     │
│ ‹ SNR = 20 dB ›  CRB 0.018°    [修改指标参数并重新计算] [复制表格]          │
└──────────────────────────────────────────────────────┴─────────────────────┘
```

### 3.1 标题、进度、警告、实验条件

| 区域 | 内容与行为 | 需求 |
|---|---|---|
| 标题栏 | 实验名、状态标签（排队 / 运行中 / 完成 / 已中止 / 失败 / 中断）；“中止”只在运行中出现；“复制并修改”把配置载入新建实验页；“重新运行”用同一份配置和种子再跑并核对结果是否一致。下方一行：实验 ID、在网页上运行还是由脚本运行、开始时间、用时 | FR-EXP-06、FR-DAT-03/04 |
| 导出数据与报告 | 菜单：`.mat`、CSV、LaTeX 表格、HTML 报告、等价的 Python 脚本。文件写入实验的 `exports/` 并下载 | FR-RES-08/11、FR-DAT-07、FR-API-06 |
| 进度 | 只在运行中显示：当前扫描点（“正在计算第 3/7 个扫描点：SNR = 0 dB”）、百分比、预计剩余时间、进度条；SSE 推送 | FR-EXP-05 |
| 警告与错误 | 放在结果之前。每条前面是该算法的样式色块和名字。警告：运行前校验给出的警告（如相干信源未平滑、超出训练范围）。错误：按类型汇总，说明出现次数、首次出现的位置、对指标的影响，可展开堆栈 | FR-ALG-09、FR-SYS-03，数据格式 4.6 |
| 实验条件 | 一句话：阵列、信源、SNR 与快拍数、阵列误差、实验方式。有算法的代码未提交时在这一行显示提示标签，不放进上面的警告列表（E6）。“查看复现信息”展开：随机种子、信号模型版本、竞技场版本与 commit、接口包版本、运行环境、设备；以及每个算法一行的表格：插件、版本、代码 commit 与未提交修改标记、模型包及哈希 | NFR-14、FR-ALG-01c、FR-GEN-08 |

### 3.2 主图

## 11. 原型没有覆盖的内容

以下按 Ant Design 的常规组件实现即可，不需要单独设计：

- “保存为模板”的命名对话框、模板编辑、添加工作目录和添加全局来源时的目录选择。
- 历史实验页的分页。
- 工作目录切换后的页面刷新。
- 二维扫描热力图（FR-EXP-09，P2）。

以下在实现时需要注意，原型做了简化：

- **失败的实验**：原型中点击只给出提示；正式界面应打开结果页，显示失败原因和 `log.txt`。
- **排队**（FR-EXP-08）：原型只演示一个任务。有排队时，导航底部的当前任务处应显示排队数，结果页的状态为“排队”。
- **“重新计算指标”的参数对话框**：由指标插件的参数 Schema 生成。
- **算法显示名重复**：原型没有校验，正式界面由后端校验给出错误（数据格式 3.9 节）。
- **K 随机、逐个信源设置 SNR、相干信源的复系数**：原型只画了入口，没有展开全部输入项，按 Schema 生成。

与其他文档的一处出入：架构 7.2 节写“能力不匹配的算法在选择列表中置灰，悬停显示原因”，本文改为原因直接显示在条目中（1.2 节“置灰必须给原因”）。本版确认后，架构文档的这句话需要同步修改。
