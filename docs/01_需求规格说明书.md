## 1. 项目概述

### 1.1 背景
需求方从事阵列信号测向（DOA估计）研究，需要在统一的仿真条件下对比传统算法与学习型算法的性能，并分析阵列误差下的鲁棒性。目前没有现成的统一测试环境，每次实验都要单独写脚本，场景参数和指标计算口径不一致，结果难以复现和对比。

### 1.2 目标
1. 在同一界面中配置阵列、信号、误差场景，选择一个或多个算法及其参数，运行实验并查看结果。
2. 同一套能力可由实验脚本以 Python API 直接调用，与 Web 界面得到相同结果。
3. 支持单次实验、蒙特卡罗统计、参数扫描三种实验方式，输出 RMSE、成功率、计算时间、CRB 等指标曲线。
4. 传统算法和学习型算法（PyTorch 预训练模型）使用同一套调用方式，可在同一实验中直接对比。
5. 开放接入：研究项目中的算法（在竞技场代码库之外）注册后即可参与评测，不修改竞技场代码。
6. 实验可复现：相同配置、相同随机种子、相同算法代码版本得到相同结果。

### 1.3 在研究室中的定位与边界

竞技场是“DOA估计研究室”的一部分。研究室按研究流程分为三个阶段：

| 阶段 | 内容 | 与竞技场的关系 |
|---|---|---|
| IDEA 选题与立项 | 文献收集（Zotero）、AI 辅助阅读、笔记（Obsidian）、形成 idea | 不在本文档范围 |
| EXP 研究执行 | Git 代码管理、实验配置、实验日志、数据管理、模型训练 | **竞技场属于本阶段**，是算法评测平台 |
| PAPER 论文写作 | LaTeX 撰写 | 竞技场导出的图表和数据供论文使用 |

竞技场有两种使用模式，地位相同，共用同一个计算核心、同一种配置格式和同一种结果文件：
- **Web 模式**：在网页端选择算法、模型和参数，后台调用算法计算，结果返回网页显示。
- **脚本模式**：实验代码通过 Python API 直接调用竞技场的场景生成、算法和指标，用于系统实验和结果整理。

职责边界：

| 竞技场负责 | 竞技场不负责（属于 EXP 其他部分或研究项目） |
|---|---|
| 统一的信号与误差模型、数据生成 | 算法本身的实现与迭代（在课题仓库中，如 `Projects/fewshot-doa`） |
| 算法注册、调用、出错隔离 | 学习型模型训练：在 AutoDL 等云 GPU 平台（Linux）上进行，训练脚本在云端调用竞技场的数据生成接口；训练好的模型下载回本机，由竞技场推理评测 |
| 模型包的导入与校验 | 云平台的使用（租用实例、上传代码、下载模型），竞技场不直接连接云平台 |
| 指标计算、CRB、可视化、导出 | 代码版本管理（竞技场只读取并记录 Git 版本） |
| 把实验配置和结果写成文件，并维护索引 | 实验结果的长期归档、备份策略（由用户在 EXP 中管理） |

关键角色：
- **竞技场核心库**：信号生成、误差模型、算法注册与调用、实验执行、指标计算。可脱离 Web 单独 import。
- **外部算法**：传统算法 A、智能算法 B 等，位于竞技场代码库之外，通过开放接口接入。V1 内置的 5 个经典算法以同一接口实现，作为基线。
- **工作目录**：用户指定的目录，存放实验配置和结果文件，可纳入 Git 或 EXP 的数据管理。

### 1.4 用户与使用环境
- 用户：需求方本人，单用户，熟悉 DOA 理论和 Python。
- 运行方式：本机运行的 Web 应用，浏览器访问 `localhost`，无需登录和权限管理；或在 Python 脚本 / Jupyter 中 import 竞技场核心库。
- 操作系统：Windows 为主。

### 1.5 范围

**第一版（V1）包含：**
- 一维（方位角）、窄带、远场信号模型
- 均匀线阵（ULA）
- 不相干、部分相关、相干信源
- 四类阵列误差：位置误差、幅相误差、阵元故障、互耦
- 5 个内置经典算法（基线）+ 1 个示例学习型算法（仅推理）
- 外部算法注册（同进程 Python）
- Web 模式与脚本模式（Python API）
- 开放数据生成接口，供外部训练脚本使用
- 单次实验、蒙特卡罗、单参数扫描
- 结果可视化、指标对比、历史记录、报告导出
- 标准场景集与排行榜（P1）

**V1 不包含，但架构上必须预留扩展点：**
- 二维 DOA（方位 + 俯仰）、宽带信号、近场信号

- 跨进程 / 跨语言算法接入（独立 conda 环境、MATLAB 等），通过适配层实现

- 导入实测数据

**明确不做：**
- 多用户、账号、远程部署
- 实时硬件采集

### 1.6 需求编号与优先级约定
- 编号格式：`FR-模块-序号`（功能需求），`NFR-序号`（非功能需求）。
- 优先级：**P0** = V1 必须有；**P1** = V1 应该有，时间不够可推迟；**P2** = 后续版本。

## 2. 术语与数学模型

本章是所有仿真和指标计算的统一口径，开发方必须严格按此实现，不得自行改变定义。

### 2.1 符号

| 符号 | 含义 |
|---|---|
| M | 阵元数 |
| K | 信源数 |
| N | 快拍数 |
| d_m | 第 m 个阵元位置（单位：波长 λ），ULA 中 d_m = m·d，m = 0…M-1 |
| θ_k | 第 k 个信源方位角（度），相对阵列法线，范围 (-90°, 90°) |
| a(θ) | 导向矢量，[a(θ)]_m = exp(-j·2π·d_m·sinθ) |
| A | 阵列流形矩阵 [a(θ_1), …, a(θ_K)]，M×K |
| R | 阵列协方差矩阵，样本估计 R̂ = X·X^H / N |

### 2.2 接收信号模型

无误差（标称）模型：

```
X = A(θ) · S + W
```
- X：M×N 接收数据；S：K×N 信源复包络；W：M×N 噪声。
- 噪声：零均值循环对称复高斯白噪声，功率 σ_n²，与信号独立。
- 信源：零均值复高斯（V1 默认）；预留确定性信号（如单频）扩展。
- 信噪比按单个信源定义：SNR_k = 10·log10(σ_k² / σ_n²)。默认所有信源 SNR 相同，允许逐个设置。

含误差的真实模型（误差只作用于“生成数据”，算法默认只知道标称阵列）：

```
X = C · Γ · A(θ; d + Δd) · S + W，然后按阵元故障设置处理 X 的对应行
```

### 2.3 信源相关性
- 信源协方差 P = E[s·s^H]，由用户设置的相关系数矩阵 ρ 和各信源功率得到：P_ij = ρ_ij·σ_i·σ_j。
- 三种模式：
  - 不相干：ρ = I
  - 部分相关：用户设置 |ρ_ij| < 1（V1 至少支持“所有信源两两相关系数相同”的简化设置）
  - 相干：ρ_ij = 1，即 s_k = α_k·s_1，α_k 为用户可设的复系数（默认幅度按 SNR、相位随机）
- 生成方法：S = L·S_0，L 为 P 的 Cholesky 分解（相干时 P 奇异，用特征分解代替）。

### 2.4 阵列误差模型

| 误差类型 | 模型 | 用户参数 |
|---|---|---|
| 位置误差 | d_m' = d_m + Δd_m，Δd_m ~ N(0, σ_p²)，单位 λ | σ_p；参考阵元（默认第 0 个）误差为 0 |
| 幅相误差 | Γ = diag(g_m·e^{jφ_m})，g_m = 1 + Δg_m，Δg_m ~ N(0, σ_g²)，φ_m ~ N(0, σ_φ²) | σ_g（线性值）、σ_φ（度）；参考阵元 g=1、φ=0；也可直接输入每个阵元的固定值 |
| 互耦 | C 为对称带状 Toeplitz 矩阵，第一行 [1, c_1, …, c_P, 0, …] | 耦合阶数 P、复系数 c_1…c_P（幅度 + 相位输入） |
| 阵元故障 | 故障阵元的输出行置零（或仅含噪声，可选） | 故障阵元下标列表，或“随机 n 个”；算法是否知道故障位置（可选） |

误差实现方式的两个选项（每类误差独立设置）：
- **固定**：一次实验内所有蒙特卡罗试验使用同一组误差值（模拟“某一具体阵列”）。
- **每次随机**：每次试验重新抽取（模拟“误差统计特性”）。

误差的作用顺序固定为：位置 → 幅相 → 互耦 → 加噪声 → 阵元故障。阵元故障的“仅含噪声”模式是在加噪声之前把故障阵元的信号分量置零；“置零”模式是在最后把整行置零。

### 2.5 性能指标定义

**估计值与真值的配对**：每次试验中，算法输出 K̂ 个角度，真值 K 个。用匈牙利算法按 |θ̂ - θ| 最小总代价配对。K̂ ≠ K 时，只配对 min(K, K̂) 对，其余记为漏检或虚警。

| 指标 | 定义 | 说明 |
|---|---|---|
| RMSE（度） | sqrt( Σ_t Σ_k (θ̂_k,t - θ_k)² / (T·K) ) | T 为试验次数。默认只在“成功检测出 K 个信源”的试验上统计，并同时给出纳入统计的试验数；可选“全部试验，缺失估计按最大误差惩罚” |
| 逐信源 RMSE | 对每个信源单独统计 | 用于观察近距离信源的差异 |
| 成功率 | 满足条件的试验占比：K̂ = K 且所有配对误差 ≤ 门限 ε | ε 由用户设置，默认 1° |
| 分辨概率 | 针对两个相邻信源 θ_1、θ_2：K̂ ≥ 2 且两个估计值分别落在 θ_i ± Δθ/2 内（Δθ = \|θ_1 − θ_2\|） | 谱类算法可选用“两峰之间谱值低于两峰均值”的经典判据 |
| 偏差 | 每个信源的平均估计误差 Σ_t(θ̂ - θ)/T | P1 |
| 计算时间 | 单次 `estimate` 调用的墙钟时间，取中位数和均值 | 不含数据生成时间；学习型算法不含模型加载时间，需注明运行设备（CPU/GPU） |
| CRB（度） | 随机（Stochastic）CRB，按标称阵列和真实信源协方差计算，sqrt 后换算为度 | 公式见 Stoica & Nehorai 1990；与 RMSE 同图展示 |

CRB 说明：
- V1 只要求计算标称（无误差）模型下的 CRB，作为理论参考线。含误差的 CRB 为 P2。
- 相干信源下 P 奇异，随机 CRB 公式仍可用，需在实现中验证数值稳定性。
- 计算 CRB 时信源数、角度、SNR、快拍数取实验的真值设置。

**信源数**：V1 默认信源数 K 作为已知量传给算法。预留“信源数估计”（AIC/MDL）作为可选前处理（P1）。

### 3.2 算法管理模块（FR-ALG）

**算法来源分两类，接口和待遇完全相同：**
- **内置算法**：随竞技场发布的经典算法，作为对比基线。
- **外部算法**：位于课题仓库中（竞技场代码库之外）的算法，例如正在研究的智能算法 B。课题仓库的 `algorithms/` 目录下每个算法一个子目录，入口文件为 `arena_plugin.py`（架构 4.4 节）。用户在竞技场配置或课题的工作目录中登记 `algorithms/` 目录（或已安装的 Python 包名），竞技场启动或刷新时加载。

**V1 内置算法：**

| 算法 | 类型 | 主要参数 | 输出 | 适用阵列 |
|---|---|---|---|---|
| CBF（常规波束形成 / Bartlett） | 谱峰搜索 | 搜索范围、网格步长 | 空间谱 + 角度 | 任意 |
| MVDR（Capon） | 谱峰搜索 | 搜索范围、网格步长、对角加载量 | 空间谱 + 角度 | 任意 |
| MUSIC | 子空间 + 谱峰搜索 | 搜索范围、网格步长、信源数、空间平滑（开/关、子阵大小、前后向） | 空间谱 + 角度 | 任意（空间平滑仅 ULA） |
| Root-MUSIC | 子空间 + 求根 | 信源数、空间平滑 | 角度 | 仅 ULA |
| ESPRIT（TLS 或 LS） | 子空间 + 旋转不变 | 信源数、LS/TLS、空间平滑 | 角度 | 仅 ULA（或具有平移不变结构的阵列） |
| 学习型示例：多标签网格分类网络（CNN） | 学习型，仅推理 | 模型文件、判决门限或取前 K 峰、推理设备 | 网格概率谱 + 角度 | 由模型元数据规定 |

空间平滑是 MUSIC 等子空间算法处理相干信源的必要手段，V1 必须实现。

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|

### 3.3 实验执行模块（FR-EXP）

三种实验类型：

| 类型 | 说明 | 主要输出 |
|---|---|---|
| 单次实验 | 生成一组数据，所有选中算法各运行一次 | 空间谱叠加图、估计角度与真值对照 |
| 蒙特卡罗 | 固定场景，运行 T 次独立试验 | 指标统计值、估计值散点 / 直方图 |
| 参数扫描 | 选一个扫描变量和取值列表，每个取值做一次蒙特卡罗 | 指标随扫描变量变化的曲线（含 CRB） |

可扫描变量（V1）：SNR、快拍数 N、两信源角度间隔、阵元数 M、信源相关系数、各类误差强度（σ_p、σ_g、σ_φ、互耦系数幅度、故障阵元数）。扫描两信源角度间隔 Δ 时，两个角度为 θc ± Δ/2（中心对称）。

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-EXP-01 | 支持上述三种实验类型 | P0 | 三类各跑通一个示例 |
| FR-EXP-02 | 同一次试验中，所有算法使用完全相同的接收数据 | P0 | 算法对比公平性可验证（记录数据种子） |
| FR-EXP-03 | 扫描取值可用“起始/终止/步长”或手动列表输入 | P0 | — |
| FR-EXP-04 | 运行前显示总运行次数估计（取值数 × 试验数 × 算法数），超过阈值时提醒 | P1 | — |
| FR-EXP-05 | 实验在后台执行，前端显示进度（当前扫描点、完成百分比、预计剩余时间） | P0 | 运行期间页面不卡死 |
| FR-EXP-06 | 可中止正在运行的实验，已完成的扫描点结果保留 | P0 | 中止后可查看部分结果 |
| FR-EXP-07 | 参数扫描时，每完成一个扫描点，结果图即时更新 | P1 | — |
| FR-EXP-08 | 同一时间只运行一个实验，其余排队 | P1 | 单用户场景下避免抢占 CPU/GPU |
| FR-EXP-09 | 支持二维扫描（两个变量组合，结果以热力图展示） | P2 | — |
| FR-EXP-10 | 可利用多核 CPU 并行执行蒙特卡罗试验，且不破坏可复现性 | P1 | 并行与串行结果一致 |

### 3.5 结果存储与历史模块（FR-DAT）

**存储原则：文件是唯一的数据来源，索引只是加速。**
- 每次实验在工作目录下生成一个独立的实验文件夹，内含配置（JSON）、结果数据（npz，可选同时导出 mat）、元信息（JSON：开始/结束时间、运行模式、竞技场版本、算法版本、运行环境）。文件格式不依赖竞技场即可读取。
- 竞技场维护一个索引（如 SQLite），只用于历史列表的检索和筛选。索引丢失或损坏时，可通过扫描工作目录完整重建。
- 工作目录可以有多个（如每个研究课题一个），用户可在 Web 端切换。工作目录可整体纳入 Git 或 EXP 的数据管理；大数据文件是否纳入 Git 由用户决定（竞技场生成默认的 `.gitignore` 建议）。

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-DAT-01 | 每次实验（Web 或脚本模式）自动存档为工作目录中的实验文件夹：完整配置（场景 + 算法及参数 + 实验类型 + 种子）、结果、运行时间、运行模式、竞技场版本、算法版本（FR-ALG-01c） | P0 | 存档中的配置可直接重新运行；用 Python 只靠 json + numpy 即可读取结果 |
| FR-DAT-01a | 索引可由工作目录完整重建；手动删除或拷入实验文件夹后，刷新即可反映 | P0 | 删除索引文件后重启，历史列表与删除前一致 |
| FR-DAT-01b | 支持多个工作目录，Web 端可切换当前工作目录 | P1 | — |
| FR-DAT-02 | 历史实验列表：按时间、名称、标签、算法、运行模式（Web / 脚本）筛选；可添加备注和标签（写回实验文件夹的元信息） | P0 | 脚本模式运行的实验同样出现在列表中，可查看图表、对比、导出 |
| FR-DAT-03 | 从历史实验“复制并修改”创建新实验 | P0 | — |
| FR-DAT-04 | 从历史实验“重新运行”，并校验结果与原结果一致 | P1 | 不一致时提示（可能算法代码已变更） |
| FR-DAT-05 | 删除实验（需二次确认；删除的是实验文件夹，默认移入工作目录内的回收区而不是直接删除） | P0 | — |
| FR-DAT-06 | 原始逐次估计值（每次试验每个算法的估计角度）随实验保存，可关闭以节省空间 | P0 | 指标可由原始值重新计算 |
| FR-DAT-07 | 报告导出：生成包含配置摘要、指标表、图表的报告（HTML 和 PDF；Word 为 P1） | P0 | 报告不依赖竞技场即可打开 |
| FR-DAT-08 | 实验配置导出/导入为 JSON 文件 | P0 | 导入后与导出前配置一致 |

## 4. 非功能需求

### 4.1 可扩展性（重点）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| NFR-01 | **接入新算法**：在竞技场代码库之外的研究项目目录中写一个 Python 文件（实现算法基类、声明参数），登记该目录后即可在 Web 和脚本中使用；不修改竞技场代码库的任何文件 | 由开发方按《算法接入指南》在一个独立目录中实现新算法（如 SBL 或 ℓ1-SVD）并接入，竞技场代码库的 `git diff` 为空 |
| NFR-01a | **算法对竞技场的依赖最小**：外部算法只依赖竞技场公开的接口包（基类、参数声明、结果类型），不依赖其内部模块 | 接口包有独立的版本号；内部模块重构不影响已接入的外部算法 |
| NFR-02 | **新增阵列类型**：只新增一个阵列类（提供阵元位置和导向矢量、声明参数），不修改信号生成、算法和前端 | 以 UCA 为例验证 |
| NFR-03 | **新增误差类型**：只新增一个误差类（作用于流形或数据），不修改其他模块 | — |
| NFR-04 | **新增指标**：只新增一个指标函数并注册 | — |
| NFR-05 | **为二维 DOA 预留扩展点，但 V1 不为它增加实现负担**：V1 中一组角度是一维数组 `(K,)`（方位角，度），不用 Python 标量；每个插件声明自己支持的角度维数（`dims`，V1 均为一维）。以后增加二维时，只新增二维插件和框架中的二维分支，已有一维插件不需要修改 | 接口评审时检查：一维插件的接口在二维扩展方案（《03_算法接口规范》12.3 节）下保持不变 |
| NFR-06 | **学习型算法接口不限定网络结构**：无论网格分类、回归还是其他输出形式，都通过统一接口返回角度 | — |
| NFR-07 | 计算核心（信号生成、算法、指标、实验执行、结果存储）与 Web 层分离；Web 后端只是核心库的一个调用方，不包含任何计算逻辑 | 可在 Jupyter 中直接调用；Web 与脚本两种模式的结果逐位一致（FR-API-02） |

## 5. 数据需求

### 5.1 实验配置（示意，正式定义见《04_数据格式规范》第 3 章）

```json
{
  "schema_version": 1,
  "name": "MUSIC vs ESPRIT, SNR扫描, 幅相误差",
  "seed": 12345,
  "scenario": {
    "array":  { "type": "ula", "params": { "M": 16, "d": 0.5 } },
    "sources": {
      "K": 2,
      "angles": { "mode": "fixed", "values": [-10.0, 10.0] },
      "snr_db": 10,
      "correlation": { "mode": "coherent" }
    },
    "snapshots": 200,
    "impairments": [
      { "type": "gain_phase", "realization": "fixed", "params": { "sigma_g": 0.05, "sigma_phi_deg": 5 } }
    ]
  },
  "algorithms": [
    { "id": "music", "label": "MUSIC+FBSS", "params": { "grid_step": 0.1, "smoothing": "fb" } },
    { "id": "esprit", "label": "TLS-ESPRIT", "params": { "method": "tls", "smoothing": "fb" } }
  ],
  "experiment": {
    "type": "sweep",
    "trials": 500,
    "sweep": { "path": "scenario.sources.snr_db", "values": [-10, -5, 0, 5, 10, 15, 20] }
  },
  "metrics": {
    "include": ["rmse", "success_rate", "resolution_prob", "time"],
    "crb": true,
    "params": { "success_rate": { "threshold_deg": 1.0 } }
  }
}
```

要点：
- 扫描变量用配置路径表示，因此任何数值型配置项原则上都可扫描。
- 算法以 `id` 引用，参数随算法声明变化，框架不解释其含义。
- 手写配置也可以用 YAML，结构相同（《04_数据格式规范》1.2 节）。

### 5.2 学习型模型元数据（随模型文件提供）

```json

  "algorithm_id": "cnn_grid",

  "input": "normalized_covariance_real_imag",
```

## 7. 典型使用流程

1. **快速对比**：打开工具 → 默认场景 → 勾选 MUSIC、ESPRIT、CBF → 单次实验 → 查看空间谱。
2. **论文出图**：加载模板 → 选算法 → 参数扫描 SNR（-10:5:20 dB），每点 500 次 → 运行 → 调整图样式 → 导出 SVG 和 `.mat`。
3. **误差鲁棒性**：开启幅相误差（每次随机）→ 扫描 σ_φ（0°–10°）→ 对比各算法 RMSE 退化。
4. **学习型算法评测**：在算法库中登记模型文件 → 实验中加入该模型和 MUSIC → 扫描快拍数 → 对比 RMSE 和耗时 → 查看是否超出训练条件提示。
5. **复现**：历史实验 → 重新运行 → 确认结果一致。
6. **接入研究中的新算法 B**：在研究项目目录中按接入指南写算法类 → 在设置页登记该目录 → 算法库中出现 B → 与内置基线对比。
7. **脚本模式系统实验**：在研究项目的实验脚本中 import 竞技场 → 用配置文件循环运行多组实验（或直接传入调试中的算法对象）→ 结果写入工作目录 → 在 Web 历史页查看图表、对比、导出论文图表。
8. **云端训练、本机评测**：研究项目代码推送到 AutoDL 等云平台 → 云端安装竞技场核心库 → 训练脚本调用数据生成接口（离线生成或 `Dataset` 在线生成）→ 训练 → 调用模型导出函数生成模型包 → 下载到本机 → 导入竞技场工作目录 → 在 Web 或脚本中与基线对比评测，查看版本一致性和训练范围提示。
9. **跑标准场景集（P1）**：选择算法 B 和基线 → 运行标准场景集 → 在排行榜查看 B 的位置 → 导出表格。
