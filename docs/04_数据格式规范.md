## 1. 通用约定

### 1.1 文本文件

| 项目 | 约定 |
|---|---|
| 编码 | UTF-8，不带 BOM（CSV 导出除外，见 4.7 节） |
| JSON 写出 | 缩进 2 个空格，键按本文定义的顺序，中文直接写出（`ensure_ascii=False`） |
| NaN / ±∞ | JSON 标准不允许，写成 `null`；读取时数值字段中的 `null` 还原为 NaN |
| 时间 | ISO 8601，带本地时区偏移，精确到秒，如 `"2026-10-29T14:30:12+08:00"` |
| 路径 | 一律用正斜杠 `/`；相对路径相对于工作目录根部，字段说明另有规定的除外 |
| 单位 | 角度用度，SNR 用 dB，阵元位置和间距用波长 λ，时长用秒（计算时间指标用毫秒，见 4.4 节） |
| 布尔与空值 | `true` / `false` / `null`，不用 0/1 或空字符串代替 |

### 1.2 手写配置可以用 YAML

用户手写的**实验配置、场景模板、实验模板、数据集配置、场景集**可以用 YAML（扩展名 `.yaml` / `.yml`），结构与 JSON 完全相同，可以写注释，键不用加引号。规则：
- 用 `yaml.safe_load` 读取，只解析标准类型，不执行任何自定义标签。
- YAML 1.1 会把未加引号的 `yes`、`no`、`on`、`off`、`y`、`n` 当成布尔值。所以插件参数的 `Literal` 取值不得使用这些词（《03_算法接口规范》5.3 节）；用户手写字符串时，拿不准就加引号。
- 竞技场**自己写出**的文件一律是 JSON。用户提交 YAML 配置运行后，实验目录中保存转换后的 `config.json`，并在 `config.source.yaml` 中原样保留用户的原文件（含注释）。
- 结果文件、元信息、`dataset.json`、`model.json` 只用 JSON。

### 1.3 版本与未知字段

- 每个 JSON 文件顶层都有 `schema_version`：实验配置为 2，其余容器为 1。格式发生不兼容变化时递增，并提供迁移（第 8 章）。
- **配置类文件**（实验配置、模板、数据集配置、场景集、竞技场配置、工作目录说明）中出现未定义的字段时，**报错**并指出字段路径，不静默忽略。原因：把 `snapshots` 拼错成 `snaphots` 时，如果静默忽略，实验会用默认值跑完而没人发现。
- **结果类文件**（`meta.json`、`summary.json`、`dataset.json`、`model.json` 等）读取时**忽略**未知字段，这样旧版本竞技场也能读新版本写出的结果。
- 配置中省略的字段取本文规定的默认值。竞技场写入实验目录的 `config.json` 会把所有默认值都填上，所以以后修改默认值不影响旧实验的重新运行。

### 1.4 npz 文件

- 实验结果用 `numpy.savez` 写出；数据集分片用 `numpy.savez_compressed`。
- 只存数值和布尔数组，**不存字符串和对象数组**，读取时使用 `np.load(path, allow_pickle=False)`（需求 NFR-44）。字符串信息（算法显示名等）放在同目录的 JSON 中，并规定数组轴的顺序与 JSON 中列表的顺序一致。
- 键名只用 ASCII 字母、数字、下划线；层级用双下划线 `__` 分隔，如 `metric__rmse__value`。
- 长度不一的数据（如每次试验的估计个数不同）用 NaN 填充到最大长度，另用一个整数数组记录实际长度。
- 浮点数默认 `float64`，复数默认 `complex128`；数据集分片的例外见 5.4 节。

### 1.5 标识符

| 标识符 | 格式 | 示例 |
|---|---|---|
| 实验 ID | `YYYYMMDD-HHMMSS_<缩写>_<4位十六进制>`；缩写由名称中的 ASCII 字母、数字转为小写，空格和其他字符变为 `-`，合并连续的 `-`，最长 24 字符；名称中没有 ASCII 字符时缩写为 `exp` | `20261029-143012_snr-sweep_a1b2` |
| 数据集 ID | 同上，缩写为空时为 `ds` | `20261029-150000_cnn-train_3f9c` |
| 评测运行 ID | 同上，缩写为空时为 `bench` | — |
| 插件 id | 见《03_算法接口规范》6.1 节 | `music` |
| 算法实例显示名 `label` | 任意字符串（可含中文），同一实验内唯一，1–40 字符 | `MUSIC+FBSS` |
| 模板名、场景集 `suite_id` | ASCII 字母、数字、`-`、`_`，同时用作文件名 | `coherent-snr-sweep` |

实验 ID 中的时间为创建时的本地时间。ID 创建后不再改变；改名只改显示名（4.3 节 `notes.json`），不改目录名。

## 3. 实验配置

实验配置描述一次完整实验：场景、算法、实验方式、指标。Web 端、`arena.run()`、`arena run config.json` 使用同一种格式。

### 3.1 顶层结构

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `schema_version` | int | 是 | 2 | 读入兼容 1；规范化写出 2 |
| `name` | str | 是 | — | 实验名称，可含中文，1–80 字符 |
| `description` | str | 否 | `""` | 说明 |
| `seed` | int | 否 | 自动 | 0 ≤ seed < 2⁶³。省略时竞技场随机生成一个，写入 `config.json`，保证实验仍可复现 |
| `scenario` | object | 是 | — | 3.2 节 |
| `search_grid` | object | 否 | `{scan_min:-90, scan_max:90, grid_step:0.1}` | 实验统一固定网格；校验起止范围及整除条件 |
| `algorithms` | list | 是 | — | 3.5 节，至少 1 项 |
| `experiment` | object | 是 | — | 3.6 节 |
| `metrics` | object | 否 | 见 3.7 节 | 3.7 节 |
| `tags` | list[str] | 否 | `[]` | 初始标签；之后以 `notes.json` 为准（4.3 节） |

迁移规则：v1 的内置谱搜索算法保留每实例网格，补齐 `grid_mode=custom`、`legacy_grid=true`；缺省 refine 补 True，显式 False 保持关闭；规范化为 peak_refinement。无网格算法及外部原生参数不注入网格。新 v2 的共享实例保存解析后的实际 scan_min/scan_max/grid_step，独立变体保持自身值。修改统一网格只影响共享实例。扫描 `search_grid.grid_step` 用于统一网格实验；扫描某实例网格字段则将该实例明确设为 custom。

### 3.2 scenario：场景

```yaml
scenario:
  array: { type: ula, params: { M: 16, d: 0.5 } }
  carrier_hz: 3.0e9          # 可选，只用于界面显示物理间距
  sources:
    K: 2
    angles: { mode: fixed, values: [-10.0, 10.0] }
    snr_db: 10
    correlation: { mode: none }
    signal: gaussian
  snapshots: 200
  noise: white_gaussian
  impairments: []
```

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `array.type` | str | `"ula"` | 阵列插件 id |
| `array.params` | object | 插件默认 | 阵列插件参数，如 ULA 的 `M`、`d` |
| `carrier_hz` | float \| null | null | 载频（Hz），只用于显示（FR-SCN-02），不影响计算 |
| `sources.K` | int 或分布 | 2 | 信源数，1 ≤ K < M。可写成分布，每次试验随机（3.3 节） |
| `sources.angles` | object | `{mode: fixed, values: [-10, 10]}` | 3.3 节 |
| `sources.snr_db` | float 或 list[float] | 10 | 单个数值：所有信源相同；列表：逐个信源，长度等于 K。噪声功率固定为 1，第 k 个信源功率为 10^(SNR_k/10)（需求 2.2 节） |
| `sources.correlation` | object | `{mode: none}` | 3.3 节 |
| `sources.signal` | str | `"gaussian"` | 信源波形。V1 只有 `gaussian`（零均值循环对称复高斯），其他取值预留（需求 Q10） |
| `snapshots` | int | 200 | 快拍数 N，N ≥ 1 |
| `noise` | str | `"white_gaussian"` | V1 只有空间白、复高斯噪声 |
| `impairments` | list | `[]` | 阵列误差，3.4 节 |

### 3.3 信源：角度、随机信源数、相关性

**角度 `sources.angles`**（三种方式）：

| `mode` | 字段 | 说明 |
|---|---|---|
| `fixed` | `values: list[float]` | 每次试验都用这组角度，长度必须等于 K |
| `random` | `min`（默认 −60）、`max`（默认 60）、`min_separation`（默认 2.0） | 每次试验在 [min, max] 内均匀抽取 K 个角度，任意两个角度的间隔不小于 `min_separation`（拒绝采样）。真值逐次记录（FR-SCN-04） |
| `separation` | `center`（默认 0）、`delta`（默认 10） | 只用于 K = 2：两个角度为 `center − delta/2` 和 `center + delta/2`。用于分辨力实验，扫描 `delta` 即“扫描两信源角度间隔”（2026-10-29 确认采用中心对称方式） |

所有角度必须在 (−90°, 90°) 内，否则校验报错。

**分布写法**：某些数值字段可以写成分布，表示每次试验（或数据集的每个样本）随机抽取。

| 写法 | 含义 |
|---|---|
| `{uniform: [a, b]}` | 在 [a, b] 上连续均匀分布 |
| `{uniform_int: [a, b]}` | 在整数 a, a+1, …, b 中等概率抽取 |
| `{choice: [v1, v2, …]}` | 在给定取值中等概率抽取 |
| `{choice: [v1, v2, …], weights: [w1, w2, …]}` | 按权重抽取，权重自动归一化 |

在实验配置中只有 `sources.K` 可以写成分布（2026-10-29 确认允许随机 K）。数据集配置中可写成分布的字段更多，见 5.2 节。

**随机信源数**：`sources.K` 写成分布（如 `{choice: [1, 2, 3]}`）时：
- 每次试验先抽取 K，再按 K 生成角度和信号。随机数路径为 `("trial", …, "K")`（架构 5.4 节）。
- 此时 `angles.mode` 只能是 `random`，`snr_db` 只能是单个数值，`correlation.phases_deg` 只能是 `"random"`。
- 算法收到的 `Observation.K` 是该次试验的真实 K（或开启信源数估计时的估计值）。
- 分辨概率只在 K = 2 的试验上统计，`n_used` 记录参与的试验数；CRB 按每次试验的 K 分别计算后平均（4.5 节）。

**相关性 `sources.correlation`**：

| `mode` | 字段 | 说明 |
|---|---|---|
| `none` | — | 信源互不相关，相关系数矩阵 ρ = I |
| `partial` | `rho: {mag: 0.5, phase_deg: 0}` | 所有信源两两之间的相关系数相同：ρ_ij = rho（i < j），ρ_ji = conj(rho)。复数，以幅度和相位表示（2026-10-29 确认）。0 ≤ mag < 1 |
| `coherent` | `phases_deg: "random"`（默认）或 `list[float]` | 第 k 个信源 s_k = α_k·s_1（需求 2.3 节）。\|α_k\| = sqrt(P_k / P_1)，由各信源 SNR 决定；α_k 的相位为 `random` 时在每次试验中于 [0°, 360°) 均匀抽取，为列表时取给定值（长度 K−1，对应 α_2…α_K） |

`partial` 的合法性：相关系数矩阵必须半正定。相位为 0（实数 ρ ≥ 0）时总是合法；**相位不为 0 且 K ≥ 3 时可能不合法**，例如 K = 3、rho = 0.9∠90° 时最小特征值为 −0.56，这样的信源无法生成。校验时计算 ρ 矩阵的最小特征值，小于 −1e-9 时报错，并给出该相位下允许的最大 `mag`。扫描 `rho.mag` 时对每个扫描点都检查。

### 3.4 impairments：阵列误差

列表，每项是一个误差插件的实例：

```yaml
impairments:
  - type: gain_phase
    realization: fixed
    params: { sigma_g: 0.05, sigma_phi_deg: 5 }
  - type: mutual_coupling
    params: { coefficients: [{mag: 0.3, phase_deg: 30}, {mag: 0.1, phase_deg: -20}] }
```

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `type` | str | — | 误差插件 id（内置：`position`、`gain_phase`、`mutual_coupling`、`element_failure`） |
| `label` | str | 等于 `type` | 同一种误差出现多次时必须用不同的 `label` 区分；配置路径用它选择（3.8 节） |
| `enabled` | bool | true | false 时不生效，但保留在配置中，便于在界面上临时关闭 |
| `realization` | `"fixed"` / `"per_trial"` | `"fixed"` | 整个实验共用一次误差实现，或每次试验重新抽取（FR-SCN-08） |
| `params` | object | 插件默认 | 由误差插件的 `Params` 校验（《03_算法接口规范》8.2 节） |

作用顺序：不同阶段按 positions → manifold → signal → output 固定顺序；同一阶段内按列表顺序（《03_算法接口规范》8.2 节）。列表为空或全部 `enabled: false` 时，数据与标称模型一致（FR-SCN-07）。

### 3.5 algorithms：算法实例

```yaml
algorithms:
  - { id: music, label: "MUSIC+FBSS", params: { smoothing: fb } }
  - { id: esprit, label: "TLS-ESPRIT", params: { method: tls, smoothing: fb } }
  - { id: cnn_grid_b, label: "B", params: { model: models/cnn_grid_m16_v3, device: cuda } }
```

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `id` | str | — | 算法插件 id；与内置插件冲突的外部插件写作 `<来源名>/<id>`（《03_算法接口规范》10.3 节） |
| `label` | str | 等于 `id` | 显示名，同一实验内唯一；图例、结果文件、配置路径都用它 |
| `params` | object | 插件默认 | 由算法插件的 `Params` 校验。写入 `config.json` 时补全全部字段 |
| `enabled` | bool | true | false 时不运行 |
| `origin` | object | — | 只出现在竞技场写出的 `config.json` 中，见下 |

**脚本传入的未登记算法**（`AlgoB.spec(...)`，《03_算法接口规范》6.6 节）在 `config.json` 中记为：

```json
{ "id": "algo_b", "label": "B-debug", "params": {"lr": 0.1},
  "origin": { "type": "script", "module": "algorithms.algo_b.arena_plugin",
              "qualname": "AlgoB",
              "file": "D:/10_Projects/DOA_Estimation/Projects/fewshot-doa/algorithms/algo_b/arena_plugin.py" } }
```

重新运行这样的实验时，竞技场先按 `module` + `qualname` 导入，失败则按 `file` 加载，再失败则提示用户登记该算法所在目录。

**模型路径**（`ModelPath` 类型参数）可以写相对路径（相对于工作目录根部）或绝对路径。Web 端选择 `models/` 中的模型包时写相对路径，这样整个工作目录换位置后实验仍可重新运行。

### 3.6 experiment：实验方式

```yaml
experiment:
  type: sweep                # single | monte_carlo | sweep
  trials: 500
  sweep:
    path: scenario.sources.snr_db
    values: [-10, -5, 0, 5, 10, 15, 20]     # 或 range: {start: -10, stop: 20, step: 5}
    label: "SNR"                             # 可选，图表横轴名
    unit: "dB"                               # 可选
  options: { workers: 1, common_random_numbers: true }
```

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `type` | `"single"` / `"monte_carlo"` / `"sweep"` | — | 三种实验方式（FR-EXP-01） |
| `trials` | int | 500 | 每个扫描点的试验次数 T，1 ≤ T ≤ 10⁶。`single` 时必须为 1（可省略） |
| `sweep` | object | — | `type: sweep` 时必填，其他类型不得出现 |
| `sweep.path` | str | — | 扫描变量的配置路径（3.8 节） |
| `sweep.values` | list[number] | — | 扫描取值，与 `range` 二选一，2–200 个 |
| `sweep.range` | `{start, stop, step}` | — | 包含 `stop`（在 1e-9 误差内）；展开后写入 `config.json` 的 `values` |
| `sweep.label` / `sweep.unit` | str | 按路径推断 | 图表横轴名称和单位 |
| `options` | object | 见下表 | — |

`sweep.path` 必须指向一个单一数值字段（int 或 float）。不能扫描列表、分布、枚举（`Literal`）和布尔字段；扫描 `int` 字段时取值必须都是整数。

常用扫描路径：

| 扫描变量 | 路径 |
|---|---|
| SNR | `scenario.sources.snr_db` |
| 快拍数 N | `scenario.snapshots` |
| 两信源角度间隔 | `scenario.sources.angles.delta`（`angles.mode` 须为 `separation`） |
| 阵元数 M | `scenario.array.params.M` |
| 相关系数幅度 | `scenario.sources.correlation.rho.mag` |
| 位置误差强度 | `scenario.impairments[position].params.sigma` |
| 幅度 / 相位误差强度 | `scenario.impairments[gain_phase].params.sigma_g` / `.sigma_phi_deg` |
| 互耦强度 | `scenario.impairments[mutual_coupling].params.scale` |
| 故障阵元数 | `scenario.impairments[element_failure].params.count` |
| 算法参数 | `algorithms[MUSIC+FBSS].params.grid_step`（只改变这一个算法实例） |

**options 字段：**

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `workers` | int | 1 | 并行进程数（架构 5.6 节）。大于 1 时计时结果会标记“仅供参考” |
| `common_random_numbers` | bool | true | 各扫描点的第 t 次试验使用同一组随机数（架构 5.4 节） |
| `source_count` | `"true"` / `"mdl"` / `"aic"` | `"true"` | 交给算法的 K 用真值，还是用 MDL / AIC 估计（FR-ALG-12） |
| `save_estimates` | bool | true | 保存逐次估计值（FR-DAT-06）。关闭后不能重新计算指标 |
| `save_spectra` | `"auto"` / `"all"` / `"none"` | `"auto"` | `auto`：只在 `single` 实验中保存空间谱；`all`：每次试验都保存（体积很大，只用于调试） |
| `save_observations` | `"auto"` / `"none"` | `"auto"` | `auto`：`single` 实验保存接收数据 X，其他类型不保存（可由种子重新生成） |
| `warmup` | bool | true | 每个算法在每个扫描点开始前，用该点第一次试验的数据**额外**调用一次 `estimate`，结果丢弃、不计时，用于排除 CUDA 初始化等一次性开销。因为预热是额外调用，所有 T 次试验都有耗时，`single` 实验也能计时 |
| `max_consecutive_errors` | int | 20 | 同一算法在一个扫描点连续出错达到此数时跳过该点剩余试验 |
| `chunk_size` | int | 64 | 试验分块大小，影响进度更新和取消响应的粒度。经典算法的结果与它无关；批量推理的学习型算法在 GPU 上可能有浮点级差异（FR-SCN-09 允许） |

### 3.7 metrics：指标

```yaml
metrics:
  include: [rmse, success_rate, resolution_prob, time]
  crb: true
  params:
    success_rate: { threshold_deg: 1.0 }
    rmse: { include_failed: false }
```

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `include` | list[str] | `[rmse, success_rate, resolution_prob, time]` | 指标插件 id（《03_算法接口规范》9.2 节）。`resolution_prob` 在 K ≠ 2 的实验中结果为 NaN |
| `crb` | bool | true | 是否计算 CRB。CRB 不是指标插件（架构 5.7 节） |
| `params` | object | `{}` | 按指标 id 给出参数，由指标插件的 `Params` 校验 |

指标只由逐次估计计算，修改 `metrics` 后可以用 `arena.recompute_metrics(实验ID)` 或 Web 端“重新计算指标”更新结果，不需要重跑实验（前提是 `save_estimates: true`）。重新计算会更新结果文件中的指标部分、`summary.json` 和 `config.json` 中的 `metrics`，并在 `meta.json` 的 `history` 中记录旧值（4.2 节）。`metrics` 不影响数据生成，所以这不破坏可复现性。

### 3.8 配置路径

配置路径用于扫描变量（3.6 节）和校验错误定位（3.9 节）。语法：

```
路径   = 段 { "." 段 }
段     = 名称 [ "[" 选择器 "]" ]
选择器 = 列表元素的 label | 从 0 开始的整数下标
```

- 列表 `scenario.impairments` 按 `label`（默认等于 `type`）选择，`algorithms` 按 `label` 选择。`label` 中含 `]` 或 `.` 时用下标。
- 示例：`scenario.impairments[gain_phase].params.sigma_phi_deg`、`algorithms[MUSIC+FBSS].params.grid_step`、`algorithms[0].params.grid_step`。
- 扫描展开时，对每个取值深拷贝配置、写入该路径，再整体校验（架构 5.3 节）。

### 3.9 语义校验规则

结构校验（类型、范围、必填、未知字段）由 Pydantic 完成。以下语义规则由竞技场在运行前、对**每个扫描点**展开后的配置检查（架构 5.3 节）。不通过的 `error` 阻止运行。

| 规则 | 路径 |
|---|---|
| 1 ≤ K < M（K 为分布时检查其最大值） | `scenario.sources.K` |
| `angles.mode = fixed` 时 `values` 长度等于 K；`separation` 时 K = 2；随机 K 时只能用 `random` | `scenario.sources.angles` |
| 所有角度在 (−90°, 90°) 内；`random` 时 `min < max`，且区间能容纳 K 个间隔 `min_separation` 的角度 | `scenario.sources.angles` |
| `snr_db` 为列表时长度等于 K | `scenario.sources.snr_db` |
| `partial` 时相关系数矩阵半正定（3.3 节）；`coherent` 时 `phases_deg` 列表长度为 K−1 | `scenario.sources.correlation` |
| 误差 `label` 唯一；算法 `label` 唯一 | `scenario.impairments`、`algorithms` |
| 误差插件、阵列插件、算法插件的 `check()` 返回的 `error` | 插件给出的参数路径 |
| `sweep.path` 存在且是单一数值字段；扫描后每个取值都通过上述全部规则 | `experiment.sweep.path` |
| 所有算法都 `enabled: false` 时不能运行 | `algorithms` |

插件 `check()` 返回的 `warning`（如快拍数小于阵元数、相干信源未开启平滑）不阻止运行，显示在界面上，并写入 `meta.json` 的 `warnings`。

校验结果在 API 和脚本中统一表示为：

```json
[
  { "level": "error", "path": "scenario.sources.angles.values",
    "message": "角度个数 3 与信源数 K=2 不一致", "sweep_index": null },
  { "level": "warning", "path": "algorithms[MUSIC].params.smoothing",
    "message": "相干信源下未开启空间平滑，MUSIC 可能失效", "sweep_index": 2 }
]
```

`sweep_index` 指出问题出现在哪个扫描点（从 0 开始），与扫描点无关时为 null。

### 3.10 完整示例

相干信源下的 SNR 扫描，对比平滑前后的 MUSIC、ESPRIT 和一个学习型算法（YAML，手写）：

```yaml
schema_version: 2
name: 相干信源 SNR 扫描（含幅相误差）
seed: 12345
scenario:
  array: { type: ula, params: { M: 16, d: 0.5 } }
  sources:
    K: 2
    angles: { mode: fixed, values: [-10, 10] }
    snr_db: 10                      # 被扫描覆盖
    correlation: { mode: coherent }
  snapshots: 200
  impairments:
    - { type: gain_phase, realization: fixed, params: { sigma_g: 0.05, sigma_phi_deg: 5 } }
algorithms:
  - { id: music, label: MUSIC }
  - { id: music, label: MUSIC+FBSS, params: { smoothing: fb } }
  - { id: esprit, label: TLS-ESPRIT, params: { method: tls, smoothing: fb } }
  - { id: cnn_grid_b, label: B, params: { model: models/cnn_grid_m16_v3 } }
experiment:
  type: sweep
  trials: 500
  sweep: { path: scenario.sources.snr_db, range: { start: -10, stop: 20, step: 5 } }
metrics:
  include: [rmse, success_rate, time]
  params: { success_rate: { threshold_deg: 1.0 } }
tags: [coherent, gain-phase]
```

运行后，实验目录中的 `config.json` 是这份配置的 JSON 形式，并补全了全部默认值：`sweep.range` 展开为 `values: [-10, -5, 0, 5, 10, 15, 20]`，每个算法实例的 `params` 补全了全部字段（例如 MUSIC 的 `grid_step: 0.1`、`subarray: null`），`experiment.options` 和 `metrics.params` 也全部写出。

**status.json**：运行进度，供 Web 端显示（架构 5.6、6.3 节）。

心跳超过 30 秒未更新且 `pid` 对应的进程不存在时，视为 `interrupted`。运行结束后保留最后一次的内容，`status` 与 `meta.json` 一致。

`display_name` 不为 null 时，历史列表显示它而不是 `config.json` 中的 `name`。创建实验时，`tags` 从配置的 `tags` 复制过来，之后只以 `notes.json` 为准。

|---|---|

按信源的指标值不放在这里，只在 `results.npz` 中。

### 4.5 results.npz：完整结果

记号：P 扫描点数，A 算法实例数，T 每点试验数，K_max 所有试验中真实信源数的最大值，L_max 所有估计个数的最大值（至少为 1），E 固定实现的误差个数。数组第二维（A）的顺序与 `summary.json` 中 `algorithms` 的顺序一致；误差的顺序与 `config.json` 中 `scenario.impairments` 里 `realization: fixed` 且 `enabled` 的项的顺序一致。

**场景与真值**

| 键 | 形状 / 类型 | 说明 |
|---|---|---|
| `sweep_values` | `(P,)` float64 | 扫描取值；非扫描实验为 `[nan]` |
| `truth` | `(P, T, K_max)` float64 | 真实角度（度），不足 K_max 处为 NaN |
| `K` | `(P, T)` int32 | 真实信源数 |
| `K_given` | `(P, A, T)` int32 | 交给算法的信源数；`source_count: true` 时与 `K` 相同 |
| `crb` | `(P,)` float64 | sqrt(CRB)，度；对信源和试验取平均（K 或角度随机时按每次试验计算后平均）；未计算时不存在此键 |
| `crb_per_source` | `(P, K_max)` float64 | 逐信源的 sqrt(CRB)；K 随机时不存在此键 |

**逐次估计**（`save_estimates: false` 时不存在）

| 键 | 形状 / 类型 | 说明 |
|---|---|---|
| `estimates` | `(P, A, T, L_max)` float64 | 原始估计角度（度），按算法返回的顺序，不足处为 NaN |
| `K_hat` | `(P, A, T)` int32 | 估计个数；出错的试验为 −1 |
| `matched` | `(P, A, T, K_max)` float64 | 与 `truth` 对齐的匹配估计，未匹配上为 NaN（需求 2.5 节） |
| `status` | `(P, A, T)` uint8 | 状态码，4.6 节 |
| `time_ms` | `(P, A, T)` float64 | 单次 `estimate` 的耗时（毫秒）；批量调用时为均摊值；未运行为 NaN |
| `resolved_by_spectrum` | `(P, A, T)` float64 | 1 / 0 / NaN，只在使用谱判据计算分辨概率时存在（《03_算法接口规范》9.2 节） |

**指标**（总是存在）

| 键 | 形状 | 说明 |
|---|---|---|
| `metric__<id>__value` | `(P, A)` float64 | 指标汇总值，与 `summary.json` 相同 |
| `metric__<id>__per_source` | `(P, A, K_max)` float64 | 按信源的值；指标不提供时不存在 |
| `metric__<id>__n_used` | `(P, A)` int32 | 参与计算的试验数 |
| `metric__<id>__extra__<名称>` | `(P, A)` float64 | 附加量，如 `metric__time__extra__mean` |

**空间谱**（只在保存空间谱时存在，`<a>` 为算法实例的序号，从 0 开始）

| 键 | 形状 | 说明 |
|---|---|---|
| `spectrum__<a>__grid` | `(G_a,)` float64 | 该算法的角度网格 |
| `spectrum__<a>__values` | `(P, T, G_a)` float64 | 线性谱值；`single` 实验中 P = T = 1 |
| `spectrum__<a>__kind` | `()` uint8 | 0 power、1 pseudo、2 probability |

**接收数据与误差实现**

| 键 | 形状 | 说明 |
|---|---|---|
| `observation__X` | `(P, T, M, N)` complex128 | 只在 `save_observations` 生效时存在（默认只有 `single` 实验） |
| `impairment__<e>__draw__<名称>` | 由插件决定 | 固定误差实现的标准化随机量，即 `sample()` 的返回值，`<e>` 为误差序号 |
| `impairment__<e>__value__<名称>` | 由插件决定 | 按第一个扫描点的参数换算得到的实际误差值（如每个阵元的增益、相位），由误差插件的 `describe()` 给出（《03_算法接口规范》8.2 节）。便于在论文中报告所用阵列的具体误差 |

每次随机（`per_trial`）的误差实现不保存，可由种子重新生成。

体积估算：P = 7、T = 1000、A = 6、K_max = L_max = 3 时，逐次估计部分约 3 MB。

### 4.6 状态码、errors.json、points/、log.txt

**试验状态码**（`results.npz` 的 `status`）：

| 码 | 名称 | 含义 |
|---|---|---|
| 0 | `ok` | 正常返回且输出合法；K̂ ≠ K 也属于正常（按漏检 / 虚警统计） |
| 1 | `exception` | `estimate` 抛出异常 |
| 2 | `bad_output` | 返回值不是 `Estimate`，或形状不对 |
| 3 | `nan_output` | 角度中有 NaN / ±∞ |
| 4 | `out_of_range` | 角度超出 [−90°, 90°] |
| 5 | `estimation_error` | 插件主动抛出 `EstimationError`（《03_算法接口规范》10.4 节） |
| 6 | `skipped` | 连续出错达到 `max_consecutive_errors` 后被跳过 |
| 7 | `not_run` | 算法 `load` / `configure` 失败，或实验被取消，未运行到 |

状态码 1–6 在成功率等指标中算作失败；状态码 7 的试验不参与任何指标的计算。

**errors.json**：错误汇总，同一种错误只保存第一次出现时的完整信息。

```json
{
  "schema_version": 1,
  "algorithms": [
    { "label": "B", "stage": "estimate",
      "errors": [ { "status": "exception", "type": "RuntimeError",
                    "message": "CUDA out of memory…", "first_at": { "point": 0, "trial": 37 },
                    "count": 2, "traceback": "Traceback (most recent call last): …" } ] }
  ]
}
```

`stage` 为 `load`、`configure`、`estimate` 之一。同一 `(label, stage, status, type, message)` 只记一项，`count` 累计次数。

**points/**：每个扫描点完成后写一个 `p_<序号三位>.npz`（如 `p_003.npz`），内容是该扫描点在 `results.npz` 中所有键的切片（第一维去掉）。实验正常结束或取消后，合并为 `results.npz`，然后**删除** `points/`。只有运行被中断（进程崩溃、被强制结束）时 `points/` 才会留下；此时在历史页点击“整理部分结果”或调用 `arena.finalize(实验ID)`，把已完成的扫描点合并为 `results.npz`，`summary.json` 的 `complete` 为 false。

**log.txt**：纯文本日志，每行格式 `2026-10-29T14:30:13+08:00 INFO [algorithm/music] 消息`，级别为 DEBUG / INFO / WARNING / ERROR。插件通过 `ctx.log` 写入的内容也在这里。

### 4.7 导出文件

导出文件按需生成，不随实验自动产生（2026-10-29 确认 `results.mat` 按需导出），写入实验目录的 `exports/`，文件名为 `<类型>_<导出时间>.<扩展名>`，如 `results_20261030-091200.mat`。导出不改变实验的其他文件。

**results.mat**（MATLAB v5 格式，`scipy.io.savemat`，`long_field_names=True`）。顶层只有一个变量 `arena`，是结构体：

| 字段 | MATLAB 类型 / 形状 | 对应 |
|---|---|---|
| `arena.name` | char | `config.json` 的 `name` |
| `arena.id` | char | 实验 ID |
| `arena.sweep.path` / `.label` / `.unit` | char | 扫描变量 |
| `arena.sweep.values` | double，P×1 | `sweep_values` |
| `arena.algorithms` | cell，A×1，每项 char | 算法实例显示名，顺序同 `summary.json` |
| `arena.metric.<id>` | double，P×A | `metric__<id>__value` |
| `arena.metric_n_used.<id>` | double，P×A | `metric__<id>__n_used` |
| `arena.crb` | double，P×1 | `crb`（未计算时为空矩阵） |
| `arena.truth` | double，P×T×K_max | `truth` |
| `arena.estimates` | double，P×A×T×L_max | `estimates`（未保存逐次估计时为空矩阵） |
| `arena.status` | double，P×A×T | `status` |

数组维度顺序与 npz 相同，MATLAB 中 `arena.metric.rmse(p, a)` 即第 p 个扫描点、第 a 个算法的 RMSE。NaN 保持为 NaN。

**中文字符的写法（已验证）**：`scipy.io.savemat` 默认把字符写成 UTF-8，但头部记录的是字符个数而不是字节数；名称或算法显示名含中文时，**MATLAB 无法加载整个文件**（2026-10-29 在本机 MATLAB R2024a + scipy 1.13.1 上验证：报错 `MATLAB:load:cantReadFile`）。竞技场导出时必须把字符数据写成 UTF-16（MAT 文件的 `miUTF16` 类型），同样环境下验证 MATLAB 可以正确读出中文名称、中文 cell 数组和 NaN。这一项列入测试：`tests/` 中保存一个含中文的 `.mat` 样例，本机有 MATLAB 时自动用 `matlab -batch` 检查能否加载。

**CSV**：每个指标一个文件 `metric_<id>_<导出时间>.csv`。第一行为表头：第一列是扫描变量（如 `SNR (dB)`），之后每列一个算法实例显示名；之后每行一个扫描点。CRB 作为单独一列 `CRB` 放在 RMSE 文件最后。编码为**带 BOM 的 UTF-8**，Windows 上用 Excel 直接打开时中文不乱码。NaN 写为空单元格。

**LaTeX 表格**（FR-RES-11）：`table_<指标>_<导出时间>.tex`，只含 `tabular` 环境，使用 booktabs（`\toprule`、`\midrule`、`\bottomrule`），每行一个扫描点、每列一个算法；可选把每行最优值加粗。算法显示名中的 LaTeX 特殊字符（`& % $ # _ { } ~ ^ \`）自动转义。

**图表**：PDF / SVG / PNG（架构 5.9 节），文件名 `fig_<图表类型>_<导出时间>.<扩展名>`。

**报告**：`report_<导出时间>.html`（自包含，图表内嵌为 SVG），可选 `report_<导出时间>.pdf`、`.docx`（架构 5.9 节）。

MAT v5 格式中单个变量不能超过 2 GB，即 double 数组不超过约 2.6 亿个元素。`estimates` 超过这个大小时（例如 P = 20、A = 10、T = 10⁵、L_max = 13），导出时提示并只导出指标部分。

### 4.8 在脚本中读取结果

不依赖竞技场时，只用标准库和 NumPy：

```
datasets/20261029-150000_cnn-train_3f9c/
```

### 5.2 数据集配置

```yaml
schema_version: 1
name: CNN 训练集（M=16，K=1~3，无误差）
seed: 2026
num_samples: 1000000
shard_size: 10000
scenario:
  array: { type: ula, params: { M: 16, d: 0.5 } }
  sources:
    K: { choice: [1, 2, 3] }
    angles: { mode: random, min: -60, max: 60, min_separation: 3 }
    snr_db: { uniform: [-10, 20] }
    correlation: { mode: none }
  snapshots: { choice: [10, 50, 200, 500] }
  impairments: []
content:
  observation: R              # R | X | both
  grid_labels: { grid: { start: -60, stop: 60, step: 1 }, sigma_deg: null }
```

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `schema_version`、`name`、`seed` | — | — | 同实验配置（3.1 节） |
| `num_samples` | int | — | 样本总数，1 ≤ num_samples ≤ 10⁹ |
| `shard_size` | int | 10000 | 每个分片的样本数（2026-10-29 确认 npz 分片） |
| `scenario` | object | — | 与实验配置的 `scenario` 结构相同（3.2–3.4 节），另外可以把更多数值字段写成分布，见下 |
| `content.observation` | `"R"` / `"X"` / `"both"` | `"R"` | 每个样本保存样本协方差 R̂、接收数据 X，或两者（2026-10-29 确认默认 R̂） |
| `content.grid_labels` | object \| null | null | 给出时每个样本附带网格多标签（FR-GEN-03） |
| `content.grid_labels.grid` | `{start, stop, step}` | — | 角度网格（《03_算法接口规范》7.4 节） |
| `content.grid_labels.sigma_deg` | float \| null | null | null：最近网格点为 1，其余为 0；数值：高斯平滑标签，在每个网格点取各信源 exp(−(θ_g − θ_k)²/(2σ²)) 的最大值 |

**数据集配置中可以写成分布的字段**（分布写法见 3.3 节）：`sources.K`、`sources.snr_db`（只能是单个数值或分布，不能是列表）、`snapshots`、`sources.correlation.rho.mag`、`sources.correlation.rho.phase_deg`，以及误差插件的数值参数（如 `impairments[gain_phase].params.sigma_phi_deg: {uniform: [0, 10]}`）。阵列参数（`M`、`d`）不能写成分布，因为同一数据集中的样本必须形状一致。

**`content.observation` 为 `X` 或 `both` 时**，`snapshots` 必须是固定值，否则样本无法堆叠成数组；校验时报错。

体积估算（M = 16）：R̂ 用 complex64 存储时每个样本约 2 KB，100 万个样本约 2 GB；X 每个样本约 0.128·N KB，N = 200 时 100 万个样本约 26 GB（npz 压缩对随机数据基本无效）。

`rho` 写成分布且 K ≥ 3 时，3.3 节的半正定检查按分布中最大的幅度、在相位分布的整个范围上进行。

### 5.4 分片内容

每个分片是 `numpy.savez_compressed` 写出的 npz，B 为该分片的样本数，K_max 为配置中信源数的最大值，G 为网格点数。

| 键 | 形状 / 类型 | 说明 |
|---|---|---|
| `index` | `(B,)` int64 | 样本的全局序号 |
| `R` | `(B, M, M)` complex64 | 样本协方差 R̂ = X·X^H / N；`observation` 为 `R` 或 `both` 时存在 |
| `X` | `(B, M, N)` complex64 | 接收数据；`observation` 为 `X` 或 `both` 时存在 |
| `angles` | `(B, K_max)` float32 | 真实角度（度），按升序排列，不足 K_max 处为 NaN |
| `K` | `(B,)` int16 | 真实信源数 |
| `snr_db` | `(B,)` float32 | 该样本的 SNR |
| `snapshots` | `(B,)` int32 | 该样本的快拍数 |
| `labels` | `(B, G)` float32 | 网格标签；配置了 `grid_labels` 时存在 |
| `param__<j>` | `(B,)` float32 | 配置中写成分布的其他字段（K、SNR、快拍数之外）的抽样值。`<j>` 是序号，对应 `dataset.json` 中 `sampled_params` 列表的第 j 项（配置路径，如 `scenario.impairments[gain_phase].params.sigma_phi_deg`）。用序号而不是把路径写进键名，是因为路径中的 `[`、`]`、`.` 和中文 label 不能作为 npz 键名（1.4 节） |

数据集分片是 1.4 节“浮点数默认 float64”的例外：生成时用 float64 / complex128 计算，**保存时转为 float32 / complex64**，体积减半。训练本身用单精度，这不损失有用的精度。每次随机的误差实现不保存（可由种子和序号重新生成）。

```json
  "weights": { "file": "model.pt", "sha256": "a91d…", "format": "state_dict" },
  "trained_on": {
    "source": "arena",
    "dataset_id": "20261029-150000_cnn-train_3f9c",
    "dataset_config": { "…": "dataset.json 中的 config，原样复制" },
    "generator_version": 1,
    "arena_version": "1.0.0",
    "notes": ""
  },
  "training": {
    "code": { "remote": "https://github.com/<用户>/fewshot-doa.git", "commit": "e3b0c44…", "dirty": false },
```

| 字段 | 必填 | 用途 |
|---|---|---|
| `model_name` | 是 | ASCII 字母、数字、`-`、`_`，也是导入后的目录名 |
| `algorithm_id` | 是 | 必须等于加载它的插件 `id`（《03_算法接口规范》7.2 节） |
| `api_version` | 是 | 导出时的 `arena_api` 主版本 |
| `array` | 是 | 与当前阵列比较（FR-ALG-06）；结构与实验配置的 `scenario.array` 相同 |
| `input` | 是 | 预处理方式的名字，由插件解释 |
| `output` | 是 | 输出形式；网格分类为 `grid_probability` + `grid` |
| `hparams` | 否 | 网络超参数，`build_network` 使用 |
| `weights` | 是 | 权重文件和哈希；加载前校验哈希。V1 中 `format` 只能是 `state_dict` |
| `trained_on.source` | 是 | `arena`：训练数据由竞技场生成；`external`：自己的生成代码，此时不做信号模型一致性检查，结果页提示“训练数据来源未知”（架构 9.2 节） |
| `trained_on.dataset_config`、`generator_version` | `source = arena` 时必填 | 训练范围判断（6.3 节）和信号模型版本检查（FR-GEN-08） |
| `training.code` | 否（导出函数会自动填写） | 与评测时插件的 commit 比较（架构 9.5 节） |
| `training` 其余字段 | 否 | 只用于在算法库页显示 |

`arena.models.export(state_dict, out_dir, model_name=…, algorithm_id=…, array=…, input=…, output=…, hparams=…, dataset=<数据集目录或配置>)` 自动填写：`schema_version`、`api_version`、`weights`（保存并计算哈希）、`trained_on`（从数据集清单复制）、`training.code`（从调用脚本所在的 Git 仓库读取）、`training.torch`、`training.gpu`、`created_at`。`training.platform`、`epochs`、`final_metrics` 等由训练脚本传入。

### 6.3 训练范围检查

`trained_on.source = arena` 时，评测前对每个扫描点，把测试场景与 `dataset_config` 比较（FR-GEN-06）。训练配置中的字段为固定值时，其“范围”就是这一个值；为分布时，`uniform` 的范围是 [a, b]，`choice` / `uniform_int` 的范围是取值集合。

| 比较项 | 判为超出训练范围的条件 |
|---|---|
| 信源数 K | 测试的 K 不在训练 K 的取值集合中 |
| SNR | 测试 SNR 不在训练范围内（容差 0.01 dB） |
| 快拍数 | 测试快拍数小于训练的最小值或大于最大值 |
| 角度 | 测试角度超出训练的 `[min, max]`；训练为 `fixed` 时，测试角度与训练角度不同 |
| 相关性 | `mode` 不同；或 `partial` 时测试的 `rho.mag` 超出训练范围 |
| 阵列误差 | 测试中出现训练中没有的误差类型；或某个数值参数超出训练范围 |

只产生 `warning`，不阻止运行。结果页在该算法、该扫描点旁显示“超出训练范围：SNR = −15 dB < −10 dB”这样的提示，并写入 `meta.json` 的 `warnings`。

### 7.2 arena_workspace.json：工作目录说明

```json

  "created_with": "1.0.0",
```

- `algorithm_sources` 是工作目录层的算法来源（2.2 节），追加在全局来源之后。其中的**相对路径相对于工作目录根部**。工作目录 `fewshot-doa/arena_ws/` 与算法目录 `fewshot-doa/algorithms/` 在同一个课题仓库中（架构 4.4 节），所以整个仓库换位置或在另一台机器上 clone 后仍然有效。`import_root` 省略时取课题仓库根目录（《03_算法接口规范》10.1 节），一般不需要写。

### 7.3 模板

**场景模板** `templates/scenario/<名称>.json`：

```json
{ "schema_version": 1, "name": "相干双信源", "description": "M=16 ULA，±10° 相干",
  "scenario": { "…": "与实验配置的 scenario 相同（3.2–3.4 节）" } }
```

**实验模板** `templates/experiment/<名称>.json`：完整的实验配置（第 3 章），另加可选字段 `"template_description"`。加载模板就是以它为初始配置新建实验，`seed` 省略时每次新建自动生成。

内置模板随软件安装（2.2 节），与工作目录中的同名模板冲突时，工作目录中的优先。

### 7.4 场景集与评测运行记录

**场景集**（FR-BEN）：内置的在 `arena` 包目录中，用户自定义的在 `<工作目录>/benchmarks/suites/<suite_id>.json`。

```json
{
  "schema_version": 1,
  "suite_id": "doa-basic",
  "version": "1.0",
  "name": "DOA 基础场景集",
  "scenarios": [
    { "name": "snr_sweep_incoherent", "description": "不相干双信源 SNR 扫描",
      "config": { "…": "实验配置，但不含 algorithms 和 name；seed 必填" } },
    { "name": "resolution", "config": { "…": "angles.mode = separation，扫描 delta" } }
  ],
  "leaderboard": [
    { "scenario": "snr_sweep_incoherent", "metric": "rmse", "at": 0, "label": "RMSE @ SNR=0 dB" },
    { "scenario": "resolution", "metric": "resolution_prob", "at": 3, "label": "分辨概率 @ Δ=4°" }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `version` | 场景集一旦发布，同一 `version` 下的内容不得修改；修改内容必须升版本。内置场景集在 `arena` 中保存哈希，加载时校验 |
| `scenarios[].config` | 不含 `algorithms`（运行时由用户选择）和 `name`（自动生成为 `<suite_id>/<场景名>`）。`seed` 必填，保证不同时间、不同算法的评测使用相同数据 |
| `leaderboard[]` | 排行榜的列。`at` 为扫描点序号（从 0 开始），非扫描实验为 0。必须显式给出，因为对不同扫描点的指标取平均通常没有意义 |

**评测运行记录** `<工作目录>/benchmarks/runs/<评测运行ID>.json`：

```json
{
  "schema_version": 1,
  "run_id": "20261030-100000_bench_77aa",
  "suite_id": "doa-basic", "suite_version": "1.0",
  "created_at": "2026-10-30T10:00:00+08:00",

```

每个场景生成一个普通实验目录（`meta.json` 的 `benchmark` 字段指回这里）。排行榜不单独保存数值，而是每次从这些实验的 `summary.json` 汇总（架构 5.11 节）。

## 8. 机器可读 Schema 与格式变更

- 竞技场的配置模型由 Pydantic 实现。`arena schema export --out <目录>` 导出本文所有配置类和结果类文件的 JSON Schema（`experiment.schema.json`、`dataset.schema.json`、`model.schema.json` 等），可用于编辑器中的自动补全和校验。插件参数部分的 Schema 由当前已加载的插件生成，所以导出结果与当前环境有关。
- **本文是格式的依据。** 代码导出的 Schema 与本文不一致时，按本文修正代码；确需改变格式时，先修改本文，并判断是否需要递增 `schema_version`。
- 递增 `schema_version` 时，竞技场提供 `arena migrate <工作目录>`，把旧格式的配置和结果文件转换为新格式，转换前在 `.trash/migrate-<时间>/` 中备份原文件。读取旧版本文件时若未迁移，竞技场在内存中转换后使用，不改写原文件。

### 9.3 开发方的默认决定（2026-10-29 需求方已全部接受）

| # | 决定 | 理由 |
|---|---|---|
| D1 | 实验结果中的估计值、指标用 float64 | 保证“同种子逐位一致”的检查不受精度影响；典型实验约 3 MB，体积可以接受 |
| D2 | 数据集分片用 float32 / complex64 | 训练用单精度；体积减半 |
| D3 | 配置类文件拒绝未知字段，结果类文件忽略未知字段 | 防止拼写错误被静默忽略；保证旧版本能读新结果 |
| D4 | 实验正常结束后删除 `points/` | 内容已全部合并进 `results.npz`，避免占用双份空间 |
| D5 | `meta.json` 不记录主机名、用户名，Git 远程地址去掉凭据 | 工作目录可能推到 GitHub |
| D6 | `single` 实验默认保存接收数据 X，其他类型默认不保存 | 单次实验便于排查算法问题；蒙特卡罗可由种子重新生成 |
| D7 | 排行榜的列必须显式指定扫描点（`at`） | 对不同扫描点的指标取平均通常没有物理意义 |
| D8 | 默认 `.gitignore` 不让 npz、数据集、模型权重进入 Git | 大文件由 EXP 的数据管理负责（2.3 节） |
