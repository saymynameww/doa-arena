- **竞技场开发者**：按本文实现 `arena_api`，并保证框架对插件的调用方式与本文一致。

**用词约定**：“必须 / 不得”是强制要求，框架会检查或测试；“应”是强烈建议，不遵守会损失某些功能（例如可复现性检查）；“可”是可选。

## 1. 范围与包结构

### 1.1 接口包内容

```
arena_api/
├── __init__.py      # 公开名称全部从这里导出；未从这里导出的名称不属于公开接口
├── types.py         # ArrayDescriptor, Observation, Estimate, Spectrum, RunContext
├── params.py        # ParamsModel, Param, ComplexValue, ModelPath
├── capabilities.py  # Capabilities
├── plugin.py        # Algorithm, ModelAlgorithm, ArrayModel, Impairment, Metric, AlgorithmSpec
├── metrics.py       # MatchedSet, MetricValue
├── model.py         # ModelMeta（model.json 的读取与校验）
├── errors.py        # 异常类型
├── grid.py          # AngleGrid
└── kit.py           # 算法工具箱：协方差、空间平滑、谱峰搜索、子空间等（只依赖 numpy）
```

依赖：`numpy`、`pydantic>=2`。`ModelAlgorithm` 在运行时需要 PyTorch，但 `arena_api` 不把 torch 列为依赖，也不在模块顶层 import torch。

`kit.py` 原先在架构文档中位于 `arena.core.algorithms.common`。现在移入接口包，外部算法使用这些工具时也只依赖 `arena_api`（NFR-01a）。内置算法同样从 `arena_api.kit` 导入。

### 1.2 版本规则

- `arena_api.__version__` 采用语义化版本。只要**主版本号**不变，按本文编写的插件无需修改即可继续使用。
- 以下变化属于不兼容变化，必须升主版本：删除或重命名公开名称；改变方法签名或调用顺序；改变数据类型的字段含义、形状或单位；收紧插件必须满足的规则。
- 以下变化只升次版本：新增可选方法（带默认实现）、新增可选字段、新增工具函数、新增 `Capabilities` 字段（带默认值）。
- 插件可声明 `api_version = 1`（主版本号，默认 1）。框架加载插件时，若主版本与当前 `arena_api` 不一致，拒绝加载并在算法库页显示原因。

## 2. 通用约定

### 2.1 单位与数值类型

| 量 | 单位 / 类型 | 说明 |
|---|---|---|
| 角度 | **度**，`float64` | 所有接口中的角度一律用度，包括估计结果、谱网格、参数。插件内部如需弧度自行转换（`np.deg2rad`） |
| 阵元位置 | 波长 λ，`float64` | 形状 `(M, 3)`，坐标 `(x, y, z)` |
| 接收数据 | `complex128` | 形状 `(M, N)` |
| 谱值 | 线性值，`float64`，非负 | 不要传 dB 值；dB 转换由图表模块完成 |
| SNR | dB | 只出现在场景配置和标签中，算法拿不到真实 SNR |
| 信源数 | `int` | — |

### 2.2 坐标系与导向矢量

- 角度 θ 相对阵列法线定义，范围 (-90°, 90°)（需求 Q1）。
- 一维 DOA 时，信源方向单位矢量为 `u(θ) = (sin θ, cos θ, 0)`：在 x-y 平面内，从 y 轴（法线）向 x 轴（阵列轴）旋转为正。
- 第 m 个阵元位置为 `p_m`，导向矢量的符号约定为

  ```
  [a(θ)]_m = exp(-j·2π·p_m·u(θ))
  ```

  ULA 阵元沿 x 轴放置，`p_m = (m·d, 0, 0)`，即得到需求 2.1 节的 `exp(-j·2π·m·d·sinθ)`。
- 第 0 个阵元是参考阵元，ULA 中位于原点。
- 二维 DOA 不在 V1 范围内。将来的方向矢量约定为 `u = (sinθ·cosφ, cosθ·cosφ, sinφ)`（θ 方位、φ 俯仰），一维情况等于 φ = 0，所以一维的符号约定在扩展后保持不变（12.3 节）。

**符号约定必须统一。** 算法若自己构造导向矢量，必须使用相同的符号，否则估计角度会整体反号。推荐直接调用 `ArrayDescriptor.steering()`，或 `kit.ula_steering()`。

### 2.3 数组形状约定

- 一组角度是一维 `float64` 数组，形状 `(K,)`，单位为度。只有一个角度时也是形状 `(1,)` 的数组，不用 Python 标量。
- 估计结果允许 K̂ = 0（形状 `(0,)`），表示没有检测到信源。
- 角度维数由插件的 `dims` 声明决定（第 4 章、8.1 节）。V1 中所有插件都是 `dims = (1,)`，本规范中出现的角度数组都是 `(K,)`。二维 DOA 的扩展方式见 12.3 节，它不改变一维插件的写法。
- 所有数组都按 NumPy 约定（C 顺序）；框架传给插件的数组是**只读**的（`writeable=False`）。

## 3. 数据类型（arena_api.types）

以下类型都是不可变的 dataclass（`frozen=True`）。字段中的数组为只读。

### 3.1 ArrayDescriptor：标称阵列描述

算法看到的阵列。它描述**标称**阵列，不包含位置误差、幅相误差和互耦，因为真实系统中算法也不知道这些误差。

```python
@dataclass(frozen=True)
class ArrayDescriptor:
    type: str                      # 阵列插件 id，如 "ula"
    params: Mapping[str, Any]      # 阵列插件参数，如 {"M": 16, "d": 0.5}
    positions: np.ndarray          # (M, 3)，单位 λ
    element_mask: np.ndarray       # (M,) bool；False 表示算法已知该阵元故障

    @property
    def M(self) -> int: ...
    @property
    def ula_spacing(self) -> float | None: ...
    def steering(self, angles: ArrayLike) -> np.ndarray: ...
    def steering_derivative(self, angles: ArrayLike) -> np.ndarray: ...
```

| 成员 | 说明 |
|---|---|
| `element_mask` | 默认全部为 True。只有当场景中阵元故障设置为“算法已知故障位置”时，才把故障阵元标为 False。未知故障时为全 True，故障阵元的数据仍会出现在 X 中（全零或只含噪声） |
| `ula_spacing` | 若所有阵元位于 x 轴上且等间距，返回间距 d（单位 λ），否则返回 None。Root-MUSIC、ESPRIT、空间平滑等依赖平移不变结构的算法用它判断是否适用，不必关心阵列插件的类型名 |
| `steering(angles)` | 输入 `(K,)` 角度（度），返回 `(M, K)` 复数导向矢量，符号约定见 2.2 节。由阵列插件提供实现 |
| `steering_derivative(angles)` | 返回对角度（**每弧度**）的导数，形状 `(M, K)`。供 CRB 和需要导数的算法使用 |

### 3.2 Observation：一次试验的观测

```python
@dataclass(frozen=True)
class Observation:
    X: np.ndarray                  # (M, N) complex128，只读
    K: int | None                  # 信源数；场景未提供或开启信源数估计时可能为估计值
    kind: Literal["narrowband"] = "narrowband"
    meta: Mapping[str, Any] = {}   # 只含算法可以合法知道的信息，见下表

    @property
    def M(self) -> int: ...
    @property
    def N(self) -> int: ...
    def covariance(self) -> np.ndarray: ...   # R̂ = X·X^H / N，(M, M)，首次调用时计算并缓存
```

- `K` 的来源：默认是场景真值（需求 2.5 节“信源数作为已知量”）。开启信源数估计（FR-ALG-12）时是 AIC/MDL 的估计值。声明 `needs_K=True` 的算法保证拿到非 None 的 K；声明 `needs_K=False` 的算法在 K 可知时同样会拿到 K，只是不能依赖它一定存在（例如 CBF 在 K 为 None 时自动改用门限取峰）。
- `meta` 中可能出现的键：`snapshots`（= N）。**不得**包含真实角度、真实 SNR、误差实现等真值信息；需要这些信息的是指标，不是算法。
- `kind` 为以后的宽带数据预留（第 12 章）。V1 中只有 `"narrowband"`。
- 同一次试验的 `Observation` 由所有算法共用（FR-EXP-02），所以 X 是只读的。算法需要修改数据时，必须先 `X.copy()`。

### 3.3 Spectrum 与 Estimate：估计结果

```python
@dataclass(frozen=True)
class Spectrum:
    grid: np.ndarray               # (G,)，角度网格（度），按升序排列
    values: np.ndarray             # (G,)，线性值，非负
    kind: Literal["power", "pseudo", "probability"] = "pseudo"

@dataclass(frozen=True)
class Estimate:
    angles: np.ndarray             # (K̂,) float64，度；K̂ 可以为 0
    spectrum: Spectrum | None = None
    info: Mapping[str, Any] = {}

    @property
    def K_hat(self) -> int: ...
    @classmethod
    def from_angles(cls, angles, spectrum=None, **info) -> "Estimate": ...
```

| 成员 | 说明 |
|---|---|
| `angles` | 估计角度，顺序任意，框架会与真值做最优匹配（需求 2.5 节）。`Estimate(...)` 构造时用 `np.asarray(angles, dtype=float64)` 转换，所以可以直接传列表；`from_angles` 是同样效果的便利写法 |
| `spectrum.kind` | `power`：功率谱（CBF、MVDR）；`pseudo`：伪谱（MUSIC 等）；`probability`：网格上的概率（学习型网格分类）。只影响图表的纵轴标注 |
| `info` | 附加信息，必须可以 JSON 序列化（数字、字符串、布尔、列表、字典），且总大小应小于 1 KB，例如 `{"n_peaks_found": 1}`、`{"K_used": 2}`。框架只在单次实验中保存它，蒙特卡罗中丢弃 |

空间谱只在单次实验中保存和显示（NFR-22）。算法在每次试验都可以返回空间谱，框架在不需要时直接丢弃；为了省时间，算法也可以查看 `RunContext.want_spectrum`，为 False 时不构造 `Spectrum`。

### 3.4 RunContext：运行上下文

```python
@dataclass
class RunContext:
    device: str                    # "cpu" 或 "cuda" / "cuda:0"
    log: logging.Logger            # 写入实验目录的 log.txt
    want_spectrum: bool            # 当前调用是否需要返回空间谱
    workspace: Path | None         # 当前工作目录；细粒度脚本调用时可能为 None
    rng: np.random.Generator       # 当前试验专用的随机数生成器，见 6.5 节

    def rng_for(self, i: int) -> np.random.Generator: ...   # 批量调用中第 i 个观测的随机数生成器
```

`RunContext` 由框架创建并维护，插件不得自己构造。插件可以把它保存在实例中，但 `rng` 在每次试验前会被框架替换，所以每次使用时都要通过 `ctx.rng` 读取，不要把某一次拿到的 `Generator` 存下来反复用。

## 4. 能力声明（Capabilities）

能力声明是静态的类属性，框架在不实例化插件的情况下读取，用于在前端置灰不适用的算法（FR-ALG-05）、决定调用方式（批量、并行、GPU）。

```python
@dataclass(frozen=True)
class Capabilities:
    array_types: tuple[str, ...] | None = None   # 支持的阵列插件 id；None 表示任意
    requires_ula: bool = False                   # 需要 ArrayDescriptor.ula_spacing 非 None
    supports_masked_elements: bool = True        # 能处理 element_mask 中的 False
    needs_K: bool = True                         # 需要已知信源数
    coherent: Literal["no", "with_smoothing", "yes"] = "no"
    dims: tuple[int, ...] = (1,)                 # 支持的角度维数；V1 只有 1，见 12.3 节
    observation_kinds: tuple[str, ...] = ("narrowband",)
    batch: bool = False                          # 实现了 estimate_batch
    parallel_safe: bool = True                   # 可在多个工作进程中各自运行一个实例
    device: Literal["cpu", "cuda", "any"] = "cpu"
```

| 字段 | 框架行为 |
|---|---|
| `array_types`、`requires_ula`、`dims`、`observation_kinds` | 不满足时该算法置灰，不能加入实验 |
| `supports_masked_elements` | 为 False 且场景设置了“算法已知故障位置”时置灰 |
| `needs_K` | 为 True 且实验开启了信源数估计时，算法收到的是估计值；若场景无法提供 K（预留情况），置灰 |
| `coherent` | 只用于提示，不置灰。场景为相干信源而算法为 `"no"` 时，界面给出黄色提示；`"with_smoothing"` 时若未开启空间平滑也给出提示（由算法的 `check()` 实现，见 6.3 节） |
| `batch` | 为 True 时框架优先调用 `estimate_batch`（FR-ALG-10） |
| `parallel_safe` | 为 False 时，即使实验设置了多进程，该算法也只在主进程中运行（架构 5.6 节） |
| `device` | `"cuda"` 或 `"any"` 的算法在界面上显示设备选项；使用 GPU 时框架计时前会同步 CUDA |

能力声明只能表达“与参数无关”的条件。与参数有关的条件（例如子阵阵元数不能超过 M、模型的阵元数与当前阵列不一致）用 `check()` 表达（6.3 节）。

## 5. 参数声明（arena_api.params）

### 5.1 基本写法

每个插件在类内部定义一个名为 `Params` 的类，继承 `ParamsModel`（它是 Pydantic `BaseModel` 的子类），每个字段用 `Param(...)` 声明：

```python
from typing import Literal
from arena_api import ParamsModel, Param

class Params(ParamsModel):
    grid_step: float = Param(0.1, gt=0, le=5, label="网格步长", unit="°")
    smoothing: Literal["none", "forward", "fb"] = Param(
        "none", label="空间平滑",
        choices={"none": "不平滑", "forward": "前向平滑", "fb": "前后向平滑"},
    )
    subarray: int | None = Param(None, ge=2, label="子阵阵元数", none_label="自动", group="空间平滑")
```

框架用 `Params.model_json_schema()` 导出 JSON Schema，前端据此自动生成表单（架构 7.2 节）；用 `Params.model_validate(dict)` 校验用户输入。插件作者不需要写任何前端代码。

所有字段都必须有默认值，这样“选中算法后直接运行”总是可行的（NFR-32）。

### 5.2 Param 的参数

`Param(default, **kwargs)` 返回一个 Pydantic `Field`，界面相关的参数写入 JSON Schema 的扩展字段。

| 参数 | 类型 | JSON Schema 字段 | 说明 |
|---|---|---|---|
| `default` | — | `default` | 必填 |
| `ge` / `gt` / `le` / `lt` | 数值 | `minimum` 等 | 范围校验 |
| `min_length` / `max_length` | int | `minItems` 等 | 列表长度 |
| `label` | str | `x-label` | 中文显示名（NFR-30）；缺省时用字段名 |
| `unit` | str | `x-unit` | 单位，显示在输入框后 |
| `help` | str | `x-help` | 说明，鼠标悬停显示 |
| `choices` | dict | `x-choice-labels` | `Literal` 取值到中文显示名的映射 |
| `none_label` | str | `x-none-label` | 字段允许 None 时，None 在界面上的显示名，如“自动”“不限” |
| `widget` | str | `x-widget` | 指定控件，见 5.4 节；缺省时按类型自动选择 |
| `group` | str | `x-group` | 分组名，同组字段放在一个折叠面板中 |
| `advanced` | bool | `x-advanced` | True 时默认收起在“高级”中 |
| `sweepable` | bool | `x-sweepable` | 能否作为扫描变量。数值字段默认 True，其余默认 False |
| `reload` | bool | `x-reload` | True 表示修改该参数需要重新 `load()`，例如模型路径。此类字段默认不可扫描（6.2 节） |
| `order` | int | `x-order` | 显示顺序，缺省按字段定义顺序 |

### 5.3 允许的字段类型

为保证前端能正确渲染（架构风险 R6），参数字段只能使用下列类型。框架加载插件时检查，出现其他类型则拒绝加载并说明原因。

| 类型 | 默认控件 | 说明 |
|---|---|---|
| `bool` | 开关 | — |
| `int`、`float` | 数字输入框 | — |
| `str` | 文本框 | — |
| `Literal["a", "b", ...]` | 下拉框（≤ 4 项时为单选按钮） | 取值必须是 ASCII 字符串，用 `choices` 给出中文名；不得使用 `yes`、`no`、`on`、`off`、`y`、`n`（大小写不限），因为 YAML 会把未加引号的这些词读成布尔值（《04_数据格式规范》1.2 节） |
| `int \| None`、`float \| None` | 数字输入框 + “自动”复选框 | 只允许数值类型可为 None |
| `list[int]`、`list[float]` | 列表编辑器 | 例如角度列表、故障阵元下标 |
| `ComplexValue` | 幅度 + 相位（度）两个输入框 | `ComplexValue(mag=0.3, phase_deg=45)`，`.value` 得到复数 |
| `list[ComplexValue]` | 复数列表编辑器 | 例如互耦系数 |
| `ModelPath` | 模型选择器 | 学习型算法的模型包路径，见第 7 章 |

不允许：嵌套的自定义 `BaseModel`、`dict`、`Union` 多种类型、`Enum` 类（用 `Literal` 代替）、`complex`（用 `ComplexValue` 代替）。

字段名必须是 ASCII 的 `snake_case`。框架保留以 `_` 开头的字段名和 `device`、`model` 两个名字（由 `ModelAlgorithm` 使用）。

### 5.4 控件名

`widget` 可取：`number`、`slider`（需同时给出上下限）、`select`、`radio`、`switch`、`text`、`angle-list`（角度列表，带范围提示）、`index-list`（阵元下标列表，按 M 校验）、`complex-list`、`model`。

### 5.5 校验

- 单字段约束用 `Param` 的 `ge`、`le` 等表达。
- 多字段之间的约束用 Pydantic 的 `model_validator(mode="after")`，校验失败时抛出 `ValueError`，消息用中文，例如 `raise ValueError("前后向平滑时子阵阵元数必须不小于 2")`。框架会把错误显示在表单上。
- 与阵列、信源数有关的约束不在 `Params` 中写，而在插件的 `check()` 中写（6.3 节），因为 `Params` 校验时拿不到阵列信息。

## 6. 算法插件（Algorithm）

### 6.1 类定义

```python
class Algorithm(abc.ABC):
    # ---- 类属性：元信息（框架不实例化即可读取）----
    id: ClassVar[str]                          # 必须；同类插件中唯一；^[a-z][a-z0-9_]{1,39}$
    name: ClassVar[str]                        # 必须；显示名，如 "MUSIC"
    version: ClassVar[str]                     # 必须；插件自己的版本号，见 10.2 节
    category: ClassVar[Literal["classical", "learning"]] = "classical"
    description: ClassVar[str] = ""           # 一两句中文简介，显示在算法库页
    references: ClassVar[tuple[str, ...]] = ()# 参考文献
    api_version: ClassVar[int] = 1
    capabilities: ClassVar[Capabilities] = Capabilities()
    Params: ClassVar[type[ParamsModel]] = ParamsModel   # 无参数时可省略

    # ---- 生命周期 ----
    def __init__(self) -> None: ...            # 不得接受参数；只做轻量初始化
    def load(self, params: Params, ctx: RunContext) -> None: ...        # 可选
    @classmethod
    def check(cls, params: Params, array: ArrayDescriptor,
              K: int | None) -> list[Issue]: ...                         # 可选
    def configure(self, params: Params, array: ArrayDescriptor,
                  ctx: RunContext) -> None: ...                          # 可选
    @abc.abstractmethod
    def estimate(self, obs: Observation, ctx: RunContext) -> Estimate: ...
    def estimate_batch(self, obs_list: Sequence[Observation],
                       ctx: RunContext) -> list[Estimate]: ...           # 可选
    def close(self) -> None: ...                                         # 可选

    # ---- 便利方法（由基类提供，插件不应覆盖）----
    @classmethod
    def spec(cls, label: str | None = None, **params) -> AlgorithmSpec: ...
    def estimate_once(self, trial, **params) -> Estimate: ...
```

最小的插件只需要 `id`、`name`、`version` 和 `estimate()`。

### 6.2 生命周期

```
                          ┌────────────── 一次实验（同一进程内）──────────────┐
__init__()                │                                                   │
load(params₀, ctx)        │  每个进程一次。params₀ 是第一个扫描点的参数         │
                          │                                                   │
for 每个扫描点:           │                                                   │
    configure(params, array, ctx)   参数或阵列与上一点不同时调用；第一个点必调 │
    for 每次试验:                                                             │
        estimate(obs, ctx)          或按块调用 estimate_batch(obs_list, ctx)   │
close()                   │  实验结束、取消或出错时都会调用                    │
                          └───────────────────────────────────────────────────┘
```

| 方法 | 用途 | 框架保证 |
|---|---|---|
| `__init__` | 初始化空状态 | 不传参数；可能被调用后立即丢弃（如只为读取信息），所以不得做耗时操作 |
| `load` | 加载与扫描无关的重资源：模型权重、大型查找表 | 每个实例只调用一次，且在第一次 `configure` 之前。多进程并行时每个工作进程各调用一次。默认实现什么都不做 |
| `check` | 静态检查参数、阵列、信源数是否匹配 | 类方法，不需要实例；框架在校验配置时（运行前、编辑表单时）对每个扫描点都调用。必须快（< 10 ms），不得读取大文件 |
| `configure` | 按当前参数和阵列预计算：导向矢量网格、选择矩阵等 | 参数或阵列描述变化时调用。参数和阵列比较的是值，不是对象身份 |
| `estimate` | 对一次试验估计角度 | 见 6.4 节 |
| `estimate_batch` | 一次处理多次试验 | 只在 `capabilities.batch=True` 时调用。默认实现逐个调用 `estimate` |
| `close` | 释放资源（显存、文件句柄） | 总会被调用，可能被调用多次，必须幂等 |

**带 `reload=True` 的参数**（如模型路径）在扫描点之间改变时，框架先 `close()`，再对同一个实例重新 `load()`、`configure()`。这种参数默认不能扫描（`sweepable=False`），因为每个点都重新加载会很慢；若作者确认加载很快，可显式设置 `sweepable=True`。

**线程与进程**：同一个实例的方法只会在一个线程中被顺序调用，插件不需要考虑线程安全。并行时每个工作进程有自己的实例（Windows 下为 spawn 方式），所以插件类和 `Params` 必须能在模块顶层 import 后创建，不得依赖运行时动态生成的类（脚本模式传入的对象除外，6.6 节）。

### 6.3 check：参数与场景的兼容性检查

```python
@dataclass(frozen=True)
class Issue:
    level: Literal["error", "warning"]
    message: str                     # 中文，告诉用户怎么改
    param: str | None = None         # 相关的参数字段名，前端据此定位

@classmethod
def check(cls, params, array, K):
    issues = []
    L = params.subarray or (array.M - (K or 1) + 1)
    if params.smoothing != "none" and array.ula_spacing is None:
        issues.append(Issue("error", "空间平滑只适用于均匀线阵", "smoothing"))
    if L > array.M:
        issues.append(Issue("error", f"子阵阵元数 {L} 超过阵元数 {array.M}", "subarray"))
    return issues
```

- `error`：配置不能运行，前端阻止提交（NFR-31）。
- `warning`：可以运行，但结果可能没有意义，例如“相干信源下未开启空间平滑”“快拍数小于阵元数”。

`check` 中只能使用 `params`、`array`、`K` 和类属性。学习型算法需要的模型元数据由 `ModelAlgorithm` 在 `check` 中读取（第 7 章）。

### 6.4 estimate：输入与输出规则

输入：
- `obs.X` 只读，所有算法共用同一份数据。
- `obs.K` 在 `needs_K=True` 时非 None。
- `ctx.want_spectrum` 告诉算法是否需要返回空间谱。

输出必须满足以下规则，框架在每次调用后检查：

| 规则 | 违反时框架的处理 |
|---|---|
| 返回 `Estimate` 对象 | 记为该次试验错误（`bad_output`） |
| `angles` 是一维数组，形状 `(K̂,)` | 形状为 `(K̂, 1)` 的二维数组会被自动展平并记一次警告；其他形状记为错误（`bad_output`） |
| `angles` 全部为有限值，且在 [-90°, 90°] 内 | 记为错误（`nan_output` / `out_of_range`） |
| K̂ 允许不等于 K | 不是错误。K̂ < K 记为漏检，K̂ > K 记为虚警，按需求 2.5 节计入指标 |
| `spectrum` 中网格与谱值长度一致、谱值非负有限 | 丢弃该谱，记警告，**不**影响角度结果 |
| `info` 可 JSON 序列化 | 丢弃 `info`，记警告 |

`estimate` 抛出的任何异常都由框架捕获，记为该次试验的错误（FR-ALG-09）。插件不需要、也不应该自己捕获所有异常再返回空结果，这会让错误被统计成“漏检”，掩盖程序问题。

需要明确表示“这次试验无法给出估计”（例如数值上确实无解）时，返回 `Estimate.from_angles([])`，并在 `info` 中写明原因。

### 6.5 随机数与确定性

- 插件内部需要随机数时（例如随机初始化的迭代算法），**只能**使用 `ctx.rng`（批量调用中第 i 个观测用 `ctx.rng_for(i)`）。不得使用 `np.random.*` 全局函数、Python `random` 模块，或自己以固定种子创建 `Generator`。这样每次试验的随机数由实验种子决定，并行与串行结果一致（架构 5.4 节）。
- 学习型算法若使用 dropout 等随机推理，同样必须由 `ctx.rng` 派生 torch 的随机种子；常规推理应处于 `eval()` 模式，不使用随机性。
- **不得**在试验之间保留会影响结果的状态（例如用上一次的估计值作为下一次的初值）。每次试验的结果只能取决于该次的观测、参数、阵列和 `ctx.rng`。这是“中止后重跑结果一致”和“并行结果一致”的前提。`configure` 中预计算的、只依赖参数和阵列的缓存不受此限制。

### 6.6 在脚本中使用算法

**引用已登记的算法**：用 `spec()` 生成一个算法实例的配置，交给 `arena.run`：

```python
# fewshot-doa/scripts/run_fig3.py，在课题仓库根目录运行：python -m scripts.run_fig3
import arena
from algorithms.algo_b.arena_plugin import AlgoB

cfg["algorithms"] = [
    arena.algorithm_spec("music", label="MUSIC+FBSS", smoothing="fb"),
    AlgoB.spec(label="B-v2", lr=0.1),          # 未登记的算法类也可以直接这样用（FR-API-04）
]
arena.run(cfg, workspace="arena_ws")
```

`spec()` 立即用 `Params` 校验参数，参数名或取值错误会在这一行就报错。传入未登记的算法类时，框架按 6.2 节的生命周期创建实例；该类所在的文件会被记录（架构 5.2 节）。

**直接调用一次估计**（调试用）：

```python
algo = AlgoB()
est = algo.estimate_once(trial, lr=0.1)    # trial 来自 arena.Scenario.sample()
```

`estimate_once` 按顺序执行 `load → configure → estimate → close`，使用 CPU 和一个由 trial 种子派生的 `RunContext`。它只用于调试和交互式探索，不写入工作目录。

**不再使用的写法**：架构文档 5.12 节示例中的 `AlgoB(lr=0.1)`（构造函数传参）不符合 6.1 节“`__init__` 不接受参数”的规定，应改为 `AlgoB.spec(lr=0.1)`。

## 7. 学习型算法插件（ModelAlgorithm）

`ModelAlgorithm` 是 `Algorithm` 的子类。它把学习型算法共同的部分做成固定流程：读取模型包、检查兼容性、构建网络、加载权重、选择设备、批量推理、计时同步。作者只需实现网络构建、预处理、后处理三个方法。

### 7.1 类定义

```python
class ModelAlgorithm(Algorithm):
    category = "learning"
    capabilities = Capabilities(batch=True, device="any", parallel_safe=False)

    class Params(ParamsModel):                 # 子类的 Params 应继承它
        model: ModelPath = Param(..., label="模型包", reload=True)
        device: Literal["auto", "cuda", "cpu"] = Param("auto", label="推理设备",
                                                       choices={"auto": "自动", "cuda": "GPU", "cpu": "CPU"})
        batch_size: int = Param(256, ge=1, le=8192, label="推理批大小", advanced=True)

    # ---- 子类必须实现 ----
    @abc.abstractmethod
    def build_network(self, meta: ModelMeta, params: Params) -> "torch.nn.Module": ...
    @abc.abstractmethod
    def preprocess(self, obs_list: Sequence[Observation], meta: ModelMeta,
                   params: Params) -> "torch.Tensor": ...
    @abc.abstractmethod
    def postprocess(self, output: "torch.Tensor", obs_list: Sequence[Observation],
                    meta: ModelMeta, params: Params, want_spectrum: bool) -> list[Estimate]: ...

    # ---- 子类可覆盖 ----
    @classmethod
    def check_model(cls, meta: ModelMeta, params: Params, array: ArrayDescriptor,
                    K: int | None) -> list[Issue]: ...   # 追加自己的兼容性检查，默认返回 []

    # ---- 基类已实现，子类不应覆盖 ----
    # load / configure / check / estimate / estimate_batch / close
```

`model` 字段没有默认值（`...`），是 5.1 节“所有字段都必须有默认值”的唯一例外：没有模型就无法运行，界面会要求用户先选择模型包。

### 7.2 基类完成的流程

| 阶段 | 基类做的事 |
|---|---|
| `check` | 读取模型包中的 `model.json`（不加载 torch，不读权重）。检查：`algorithm_id` 等于本插件 `id`；`api_version` 主版本一致；模型的阵列类型、阵元数 M、间距与当前阵列一致（FR-ALG-06）；然后调用子类的 `check_model`。不一致时返回 `error`。另外产生以下 `warning`：信号模型版本 `GENERATOR_VERSION` 与当前不同（FR-GEN-08）；训练数据来源未知；训练代码的 commit 与当前插件的 commit 不同（架构 9.5 节） |
| `load` | 在这里才 `import torch`。确定设备：`auto` 时有 CUDA 用 `cuda`，否则用 `cpu`；选择 `cuda` 但没有 CUDA 时报错。校验权重文件 SHA-256 与 `model.json` 一致。调用 `build_network(meta, params)`，然后 `torch.load(path, map_location=device, weights_only=True)` 并 `load_state_dict(strict=True)`；缺失或多余的参数名会原样显示在错误信息中。最后 `net.eval()` |
| `estimate_batch` | 按 `batch_size` 切块；对每块：`preprocess` → 移到设备 → `torch.inference_mode()` 下前向计算 → `postprocess`。计时由框架负责（含 CUDA 同步） |
| `estimate` | 等价于 `estimate_batch([obs])[0]` |
| `close` | 删除网络引用；使用 CUDA 时调用 `torch.cuda.empty_cache()` |

子类的 `preprocess` 返回 CPU 或设备上的张量都可以，基类会统一移到推理设备。`postprocess` 收到的 `output` 在推理设备上，子类自行 `.cpu()`。

### 7.3 ModelPath 与 ModelMeta

`ModelPath` 是一个字符串类型，取值为模型包目录的路径。前端的模型选择器列出 `<工作目录>/models/` 下已导入的模型包（FR-ALG-14），也允许手工输入绝对路径。存入实验配置时保存为用户输入的路径；结果的 `meta.json` 中另外记录解析后的绝对路径和权重文件哈希（FR-ALG-06）。

`ModelMeta` 是 `model.json` 的只读视图。下表只列插件常用的字段，完整字段定义在《04_数据格式规范》中：

| 字段 | 类型 | 说明 |
|---|---|---|
| `algorithm_id` | str | 对应的插件 id |
| `array` | dict | `{"type": "ula", "params": {"M": 16, "d": 0.5}}`，与实验配置的 `scenario.array` 结构相同 |
| `output` | dict | 输出形式，网格分类为 `{"type": "grid_probability", "grid": AngleGrid}` |
| `input` | str | 预处理方式的名字，由插件自己解释，例如 `"normalized_covariance_real_imag"` |
| `hparams` | dict | 网络超参数（层数、通道数等），供 `build_network` 使用 |
| `trained_on` | dict | 训练数据集配置（内嵌）或来源说明 |
| `generator_version` | int \| None | 训练数据的信号模型版本；None 表示训练数据不是由竞技场生成 |
| `path` | Path | 模型包目录（运行时由框架填入） |

**网络结构由插件代码决定，超参数由模型包决定。** 同一个插件可以加载不同超参数训练出的多个模型包，`build_network` 读取 `meta.hparams` 构建对应的网络。

### 7.4 角度网格（AngleGrid）

学习型网格分类模型、数据集标签（FR-GEN-03）和谱峰搜索共用同一种网格定义：

```python
@dataclass(frozen=True)
class AngleGrid:
    start: float          # 度
    stop: float           # 度，包含端点
    step: float           # 度

    @property
    def points(self) -> np.ndarray: ...     # (G,)，np.round(start + k·step, 10)，k = 0…G-1
    @property
    def size(self) -> int: ...              # G = round((stop - start)/step) + 1
    def index_of(self, angles) -> np.ndarray: ...   # 最近网格点下标
```

`(stop - start)/step` 必须在 1e-9 的误差内是整数，否则构造时报错。JSON 中写成 `{"start": -60, "stop": 60, "step": 1}`。

## 8. 阵列插件与误差插件

### 8.1 ArrayModel：阵列插件

```python
class ArrayModel(abc.ABC):
    id: ClassVar[str]                  # 如 "ula"
    name: ClassVar[str]                # 如 "均匀线阵"
    version: ClassVar[str]
    dims: ClassVar[tuple[int, ...]] = (1,)
    Params: ClassVar[type[ParamsModel]]

    @abc.abstractmethod
    def positions(self, params: Params) -> np.ndarray: ...          # (M, 3)，单位 λ
    def steering(self, angles: np.ndarray, positions: np.ndarray) -> np.ndarray: ...
    def steering_derivative(self, angles: np.ndarray, positions: np.ndarray) -> np.ndarray: ...
    @classmethod
    def check(cls, params: Params) -> list[Issue]: ...
```

- 只有 `positions` 必须实现。`steering` 和 `steering_derivative` 的默认实现按 2.2 节的平面波公式计算，对任意几何阵列都成立。只有非平面波模型（如以后的近场）才需要覆盖。
- `steering` 接收的 `positions` 可能是带位置误差的实际位置（数据生成时），也可能是标称位置（`ArrayDescriptor.steering`），所以必须使用传入的 `positions`，不得在内部重新计算。
- 阵列插件不处理幅相误差和互耦，它们由误差插件处理。

V1 内置 ULA：

| 参数 | 类型 | 默认 | 约束 |
|---|---|---|---|
| `M` | int | 16 | 2 ≤ M ≤ 128（FR-SCN-01） |
| `d` | float | 0.5 | 0 < d ≤ 2，单位 λ；d > 0.5 时 `check` 给出“可能出现栅瓣”的警告 |

### 8.2 Impairment：误差插件

```python
class Impairment(abc.ABC):
    id: ClassVar[str]                  # 如 "gain_phase"
    name: ClassVar[str]
    version: ClassVar[str]
    stage: ClassVar[Literal["positions", "manifold", "signal", "output"]]
    Params: ClassVar[type[ParamsModel]]

    @abc.abstractmethod
    def sample(self, rng: np.random.Generator, M: int) -> Mapping[str, np.ndarray]: ...
    @abc.abstractmethod
    def apply(self, data: np.ndarray, draw: Mapping[str, np.ndarray], params: Params) -> np.ndarray: ...
    def known_mask(self, draw, params, M: int) -> np.ndarray | None: ...   # 可选
    def describe(self, draw, params, M: int) -> Mapping[str, np.ndarray]: ...   # 可选
    @classmethod
    def check(cls, params: Params, M: int) -> list[Issue]: ...
```

**`sample` 与 `apply` 分开**是为了满足架构 5.4 节的要求：扫描误差强度时，误差的“形状”保持不变，只改变大小。
- `sample(rng, M)` 只抽取**与强度参数无关**的标准化随机量（例如标准正态分布的 `z_g`、`z_phi`、故障阵元的随机排列），返回一个由数组组成的字典，称为一次“误差实现”。它不接收 `params`，从接口上保证了这一点。
- `apply(data, draw, params)` 把强度参数作用到标准化随机量上，再作用于数据。例如幅相误差：`g = 1 + sigma_g·z_g`，`φ = sigma_phi·z_phi`，`Γ = diag(g·e^{jφ})`。

`stage` 决定 `apply` 接收和返回什么，以及调用时机（架构 5.5 节，顺序与需求 2.4 节一致）：

| `stage` | `data` 输入 / 输出 | 内置插件 |
|---|---|---|
| `positions` | 阵元位置 `(M, 3)` → 实际位置 `(M, 3)` | 位置误差 `position` |
| `manifold` | 真实流形 `A` `(M, K)` → 修改后的流形 `(M, K)` | 幅相误差 `gain_phase`、互耦 `mutual_coupling` |
| `signal` | 无噪数据 `A·S` `(M, N)` → `(M, N)` | 阵元故障 `element_failure`（“仅含噪声”模式） |
| `output` | 含噪数据 `X` `(M, N)` → `(M, N)` | 阵元故障 `element_failure`（“置零”模式） |

同一阶段有多个误差时，按实验配置中列出的顺序依次作用。互耦与幅相误差都在 `manifold` 阶段，内置配置中幅相误差排在前（`C·Γ·A`，需求 2.2 节）。

阵元故障一个插件对应两种模式。为此 `stage` 可以是由参数决定的：插件可把 `stage` 定义为类方法 `stage_for(params)`，框架优先调用它；未定义时使用类属性 `stage`。

**known_mask**：返回 `(M,)` 布尔数组时，框架把它作为 `ArrayDescriptor.element_mask` 传给算法（“算法已知故障位置”，需求 2.4 节）。默认返回 None，表示算法不知道。

**describe**：把一次误差实现换算成人能直接看懂的实际误差值，返回由数值数组组成的字典，如幅相误差返回 `{"gain": (M,), "phase_deg": (M,)}`，位置误差返回 `{"offset": (M, 3)}`。框架对固定实现的误差按第一个扫描点的参数调用它，结果保存在 `results.npz` 中（《04_数据格式规范》4.5 节），便于在论文中报告所用阵列的具体误差。默认返回空字典。内置的四个误差插件都必须实现。

**固定 / 每次随机**（FR-SCN-08）由框架实现，插件不需要关心：固定时整个实验只调用一次 `sample`，用随机数路径 `("fixed", 误差序号)`；每次随机时每次试验调用一次。

**`apply` 必须是纯函数**：不修改输入数组，不保存状态，相同输入得到相同输出。

V1 内置误差插件的参数：

| 插件 | 参数 | 说明 |
|---|---|---|
| `position` | `sigma`（λ，默认 0.01）、`axes`（`"x"` / `"xy"` / `"xyz"`，默认 `"x"`）| 参考阵元（第 0 个）误差为 0 |
| `gain_phase` | `sigma_g`（线性，默认 0.05）、`sigma_phi_deg`（度，默认 5）、`fixed_gains`、`fixed_phases_deg`（`list[float] \| None`，给出时忽略随机量，按给定值） | 参考阵元 g = 1、φ = 0 |
| `mutual_coupling` | `coefficients`（`list[ComplexValue]`，c₁…c_P，默认 `[0.3∠30°, 0.1∠-20°]`）、`scale`（`float`，默认 1.0，所有系数的幅度乘以它，用于扫描互耦强度） | 互耦是确定性的，`sample` 返回空字典 |
| `element_failure` | `indices`（`list[int] \| None`，指定故障阵元）、`count`（`int`，未指定 `indices` 时随机选 count 个）、`mode`（`"zero"` / `"noise_only"`）、`known`（`bool`，算法是否知道故障位置）| 随机选择时排除第 0 个阵元。`count` 可扫描：`sample` 生成全部 M−1 个候选阵元的随机排列，`apply` 取前 `count` 个，所以 count 增大时原有的故障阵元保持不变 |

## 9. 指标插件（Metric）

### 9.1 输入：MatchedSet

框架对一个扫描点、一个算法的全部 T 次试验做完匹配（需求 2.5 节）后，把结果整理为 `MatchedSet` 交给指标插件。指标插件不需要自己做匹配。

```python
@dataclass(frozen=True)
class MatchedSet:
    truth: np.ndarray        # (T, K_max)，真值角度，不足 K_max 处为 NaN
    K: np.ndarray            # (T,) int，每次试验的真实信源数
    estimates: np.ndarray    # (T, K̂_max)，原始估计，不足处为 NaN
    K_hat: np.ndarray        # (T,) int，每次试验的估计数；出错的试验为 -1
    matched: np.ndarray      # (T, K_max)，与 truth 对齐的匹配估计；未匹配上为 NaN
    error: np.ndarray        # (T, K_max)，|matched − truth|（度）；未匹配为 NaN
    failed: np.ndarray       # (T,) bool，该次试验出错（异常、坏输出）
    time_ms: np.ndarray      # (T,) float，单次 estimate 耗时（毫秒），不含预热调用；未运行为 NaN
    spectra: Sequence[Spectrum | None] | None   # 仅单次实验时提供
    extra: Mapping[str, np.ndarray]   # 框架在试验过程中逐次计算的量，如 "resolved_by_spectrum"
    context: Mapping[str, Any]   # 扫描点的场景参数，如 {"snr_db": 10, "snapshots": 200}
```

角度误差直接取差值，不做 360° 环绕处理，因为一维 DOA 的角度范围是 (-90°, 90°)，不存在环绕。

### 9.2 类定义与输出

```python
@dataclass(frozen=True)
class MetricValue:
    value: float                         # 汇总值；无法计算时为 NaN
    per_source: np.ndarray | None = None # (K_max,)，可选
    n_used: int | None = None            # 参与计算的试验数（例如 RMSE 剔除失败试验后的数量）
    extra: Mapping[str, float] = {}      # 可选附加量，如置信区间上下限

class Metric(abc.ABC):
    id: ClassVar[str]                    # 如 "rmse"
    name: ClassVar[str]                  # 如 "RMSE"
    version: ClassVar[str]
    unit: ClassVar[str] = ""             # 如 "°"、"%"、"ms"
    higher_is_better: ClassVar[bool] = False   # 排行榜排序方向
    log_axis: ClassVar[bool] = False     # 曲线图默认纵轴是否用对数
    Params: ClassVar[type[ParamsModel]] = ParamsModel

    @abc.abstractmethod
    def compute(self, ms: MatchedSet, params: Params) -> MetricValue: ...
```

- 指标参数（例如成功门限 ε）在实验配置的 `metric_params` 中设置，修改后可以不重跑实验直接重新计算（架构 5.7 节），所以 `compute` 只能使用 `MatchedSet` 和参数，不能依赖其他状态。
- `compute` 必须是纯函数，结果只由输入决定。
- CRB 不是指标插件，而是由核心库按场景计算的理论值（架构 5.7 节），在图表中与 RMSE 画在一起。

V1 内置指标：

| id | 名称 | 参数 | 定义 |
|---|---|---|---|
| `rmse` | RMSE（°） | `include_failed`（`bool`，默认 False）、`penalty_deg`（`float`，默认 90，`include_failed` 为 True 时未匹配的估计按此误差计） | 需求 2.5 节；默认只用 K̂ = K 且未出错的试验，`n_used` 为参与的试验数 |
| `bias` | 偏差（°） | — | 每个信源的平均有符号误差 |
| `success_rate` | 成功率（%） | `threshold_deg`（默认 1.0） | K̂ = K 且全部配对误差 ≤ ε |
| `resolution_prob` | 分辨概率（%） | `criterion`（`"halfgap"` / `"spectrum"`，默认 `"halfgap"`） | 需求 2.5 节；只对 K = 2 的场景有定义，否则为 NaN。`"spectrum"` 判据（两峰之间谱值低于两峰均值）需要空间谱：为避免保存每次试验的谱（NFR-22），框架在每次 `estimate` 返回后立即做这一判断，只把结果存为 `MatchedSet.extra["resolved_by_spectrum"]`（`(T,)` bool）；不返回空间谱的算法此项为 NaN |
| `time` | 计算时间（ms） | `stat`（`"median"` / `"mean"`，默认 `"median"`） | 不含预热调用；`extra` 中同时给出均值和中位数 |
| `detection_accuracy` | 信源数正确率（%） | — | K̂ = K 的比例；开启信源数估计时用于评价 AIC/MDL（FR-ALG-12） |

## 10. 插件的发现、标识与版本

### 10.1 框架如何找到插件

架构 5.2 节规定了三种来源。对算法作者来说，规则如下：

**目录来源**（最常用，对应竞技场配置中的 `{"type": "path", "value": ...}`）。登记的是课题仓库中的 `algorithms` 目录（架构 4.4 节）：

```json
{ "type": "path", "value": "D:/10_Projects/DOA_Estimation/Projects/fewshot-doa/algorithms" }
```

**一个算法一个子目录，竞技场只导入每个子目录中的 `arena_plugin.py`：**

```
algorithms/
├── cnn_grid/
│   ├── arena_plugin.py    ← 只导入这个文件
│   ├── net.py             ← 被 arena_plugin.py import 时才加载
│   └── train.py           ← 竞技场永远不导入
├── common/                ← 没有 arena_plugin.py，不当成算法
└── _draft/                ← 以 _ 开头，跳过
```

- 框架只看 `value` 下的**第一层子目录**。子目录名以 `_` 或 `.` 开头、或是 `__pycache__` 时跳过；没有 `arena_plugin.py` 的子目录也跳过。子目录中的其他 `.py` 文件（训练脚本、数据处理脚本）不会被扫描或导入，所以训练脚本中的顶层代码不会在竞技场启动时被执行。
- 每个算法子目录作为一个独立的包加载，包名为 `arena_ext.<来源序号>.<子目录名>`，入口模块为该包下的 `arena_plugin`。不同来源中同名的子目录不会冲突。
- **导入同一算法子目录中的文件用相对导入**：`from .net import CnnGrid`。
- **导入课题仓库中其他目录的代码用绝对导入**：`from algorithms.common.utils import load_cfg`。为此，框架加载前把 `import_root` 加入 `sys.path`。`import_root` 缺省为 `value` 所在 Git 仓库的根目录（即课题仓库根目录）；不是 Git 仓库时为 `value` 的上一级目录。一般不需要填写。
- 同一进程中登记了两个课题仓库时，两者的 `algorithms.common` 会因为同名而冲突。所以跨目录的绝对导入只用于本课题仓库内部；两个课题都要用的代码应拆成单独的算法仓库（架构 4.4 节）。
- 入口模块中凡是满足以下条件的类都被注册：是 `Algorithm`、`ArrayModel`、`Impairment` 或 `Metric` 的子类；定义在该模块中（不是 import 进来的）；不是抽象类；类属性 `id` 存在。一个 `arena_plugin.py` 中可以定义多个插件类（如同一算法的两个变体）。想放一个不注册的辅助基类时，把它命名为以 `_` 开头，或不定义 `id`。
- 多进程并行时，工作进程按 `(类别, id)` 在自己的注册表中重新加载插件，不在进程之间传递插件类本身。

训练脚本（如 `cnn_grid/train.py`）与竞技场无关，按普通 Python 脚本运行。建议在课题仓库根目录用模块方式运行：`python -m algorithms.cnn_grid.train`，这样训练脚本中可以写 `from algorithms.cnn_grid.net import CnnGrid`，与插件使用同一份网络定义。

**单文件写法**：只有一个文件的简单算法，也可以直接把 `.py` 文件放在 `value` 下的第一层（文件名不以 `_` 开头），竞技场同样导入它。因此 `value` 第一层不要放脚本。课题仓库中推荐统一使用子目录写法。

**包来源**：已安装的 Python 包在 `pyproject.toml` 中声明入口点，值为模块路径：

```toml
[project.entry-points."doa_arena.plugins"]
doa_baselines = "doa_baselines.algorithms"
```

框架按与目录来源相同的规则处理该包：导入每个子包中的 `arena_plugin` 模块，以及第一层的模块。

**脚本传入**：`AlgoB.spec(...)` 传入的类不需要任何登记（6.6 节）。多进程并行（`workers > 1`）时，这个类必须定义在可以 import 的模块中；定义在脚本自身（`__main__`）中的类只能在主进程中运行，框架会给出警告。

### 10.2 id 与 version

- `id` 一经使用就不要再改。实验配置、历史结果和排行榜都按 `id` 引用算法；改了 `id`，旧实验就无法重新运行，排行榜上也会变成另一个算法。
- 想保留旧算法、同时发布一个行为不同的新算法时，用新的 `id`（例如 `algo_b` → `algo_b2`）。
- `version` 是插件作者自己维护的版本号，推荐 `主.次.修订`。**修改可能影响估计结果时必须更新 version**：改算法逻辑、改参数默认值、改参数含义。只改注释、日志、性能（结果不变）时可以不改。
- 框架同时记录 Git commit 和未提交改动（架构 5.2 节），所以 version 不是复现的唯一依据；它的作用是让人一眼看出“这两个结果用的是不是同一版算法”，并作为排行榜分组的依据。

### 10.3 加载失败的情况

以下情况插件不会被注册，算法库页显示原因（FR-ALG-01b），其他插件不受影响：

| 情况 | 显示的原因 |
|---|---|
| 文件有语法错误或 import 失败 | 异常信息和堆栈 |
| 缺少 `id`、`name`、`version`，或 `id` 格式不符 | 缺少哪个属性 |
| `Params` 使用了 5.3 节以外的类型，或有字段没有默认值（`ModelAlgorithm.model` 除外） | 字段名和类型 |
| `Params.model_json_schema()` 失败 | 异常信息 |
| `api_version` 主版本不一致 | 插件要求的版本和当前版本 |
| `id` 与内置插件冲突 | 不拒绝，以 `<来源名>/<id>` 注册并提示（架构 5.2 节） |
| `id` 与另一个外部插件冲突 | 两者都拒绝，提示冲突的文件 |

### 10.4 异常类型（arena_api.errors）

| 异常 | 用途 | 抛出者 |
|---|---|---|
| `ArenaError` | 所有竞技场异常的基类 | — |
| `PluginError` | 插件定义不合规 | 框架 |
| `ConfigError` | 配置不合法，带 `path`（配置路径）和中文 `message` | 框架；插件在 `configure` / `load` 中发现无法继续时也可抛出 |
| `ModelLoadError` | 模型包缺失、哈希不符、权重与网络不匹配 | `ModelAlgorithm` |
| `EstimationError` | 插件主动报告某次试验无法计算（例如矩阵奇异且无法处理） | 插件，可选 |

插件在 `estimate` 中可以抛出任何异常，框架都会捕获（6.4 节）。抛出 `EstimationError` 的好处是错误信息更清楚，在结果中按 `message` 分类统计。

## 11. 算法工具箱（arena_api.kit）

内置算法使用的公共函数，外部算法可以直接使用，也可以完全不用。全部只依赖 NumPy，输入输出都是 NumPy 数组，角度单位为度。

| 函数 | 说明 |
|---|---|
| `ula_steering(angles, M, d) -> (M, K)` | ULA 导向矢量，`angles` 为 `(K,)`，符号约定见 2.2 节 |
| `sample_covariance(X) -> (M, M)` | R̂ = X·X^H / N |
| `forward_backward(R) -> (M, M)` | 前后向平均 (R + J·R*·J) / 2 |
| `spatial_smoothing(R, L, fb=False) -> (L, L)` | 前向（或前后向）空间平滑，子阵阵元数 L；要求 ULA |
| `auto_subarray(M, K, fb) -> int` | 子阵阵元数的自动取值，见 13.2 节 |
| `eig_subspaces(R, K) -> (Es, En, eigvals)` | 特征分解，按特征值降序返回信号子空间、噪声子空间和特征值 |
| `diagonal_loading(R, ratio) -> R'` | R + ratio·tr(R)/M·I |
| `grid_spectrum(A_grid, f) -> (G,)` | 对网格导向矢量矩阵逐列计算谱值的通用辅助 |
| `find_peaks_1d(grid, values, K, min_sep_deg=0, refine=True) -> (K̂,)` | 在谱上找最多 K 个峰：只取局部极大值，按峰值降序；`refine=True` 时用抛物线插值细化到网格点之间；局部极大值不足 K 个时返回实际找到的个数 |
| `find_peaks_threshold(grid, values, rel_db) -> (K̂,)` | 找出所有高于最大值 `rel_db` dB 以内的局部极大值，用于 K 未知的情况 |
| `mdl(eigvals, N) / aic(eigvals, N) -> int` | 信源数估计（FR-ALG-12） |

这些函数的行为和数值精度由竞技场的测试覆盖，修改时遵守 1.2 节的版本规则。

## 12. 预留接口（V1 不实现）

本章只规定接口的形状，保证 V1 的设计不阻碍它们。V1 中框架不会调用这些接口；插件若实现了它们，V1 会忽略。

### 12.1 少样本适配（FR-ALG-11）

```python
class AdaptiveMixin:
    def adapt(self, support: Sequence[tuple[Observation, np.ndarray]], ctx: RunContext) -> None:
        """在测试前用少量带标签样本 (观测, 真实角度 (K,)) 适配模型。"""
```

将来 runner 在每个扫描点的 `configure` 之后、第一次 `estimate` 之前调用 `adapt`。支持集用随机数路径 `("trial", ..., "adapt")` 生成（架构 5.4 节），与测试数据独立。实验配置中增加支持集大小（shot 数）和支持集场景（可与测试场景不同，用于模拟域偏移）。适配是否在每个扫描点重新开始、是否允许跨扫描点累积，到时再定。

### 12.2 跨进程 / 跨语言算法（FR-ALG-13）

```python
class RemoteAlgorithm(Algorithm):
    """把运行在另一个进程中的算法包装为普通 Algorithm。"""
    transport: ClassVar[Literal["subprocess", "matlab_engine", "http"]]
```

将来的实现：`load` 时启动或连接远端（独立 conda 环境的 Python 进程、MATLAB Engine），`estimate` 时把 `Observation` 序列化后发送，收到角度后构造 `Estimate`。对框架来说它只是一个普通的 `Algorithm`，计时会包含通信开销，结果中会标明。

### 12.3 二维 DOA 与宽带信号

- **二维 DOA**：V1 只预留 `dims` 声明，不预留数组形状。将来的规则：
  - 插件声明 `Capabilities.dims = (2,)`（阵列插件同样声明 `dims = (2,)`）后，它收发的角度为 `(K, 2)`（第二列为俯仰角），`Spectrum.grid` 为 `(G, 2)`。
  - 声明 `dims = (1,)` 的插件（即全部 V1 插件）继续使用 `(K,)`，代码不需要任何修改；在二维场景中它们自动置灰。
  - 框架按实验的维数选择一维或二维的匹配、指标和图表实现。`MatchedSet` 增加二维版本，`Metric` 插件通过类属性 `dims` 声明自己支持的维数，默认 `(1,)`。
  - 以上都是新增内容，不改变一维插件的接口，按 1.2 节只需升次版本。
- 宽带：`Observation.kind = "wideband"`，增加频点信息字段。只声明 `observation_kinds = ("narrowband",)` 的现有插件自动置灰。

## 13. 内置算法规格

内置算法是对比基线，其实现方式直接影响论文中的对比结论，所以在这里写明，开发方不得自行改变。所有内置算法都按本文的接口实现，与外部算法没有任何特权差别。

### 13.1 公共参数与公共规则

谱峰搜索类算法（CBF、MVDR、MUSIC）共有的参数：

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `scan_min` / `scan_max` | float | -90 / 90 | 搜索范围（°），`check` 要求 scan_min < scan_max |
| `grid_step` | float | 0.1 | 网格步长（°），0 < step ≤ 5 |
| `refine` | bool | True | 抛物线插值细化峰位置 |
| `peak_mode` | `"top_k"` / `"threshold"` | `"top_k"` | 取前 K 个峰，或取高于最大值 `peak_threshold_db` 以内的所有峰 |
| `peak_threshold_db` | float | 10 | `peak_mode="threshold"` 时使用 |

公共规则：
- 网格包含两个端点，端点上的值不算局部极大值（避免把边缘的单调上升当成峰）。
- 局部极大值少于 K 个时，返回实际找到的个数（K̂ < K），**不**补齐，按漏检计入指标。在 `info` 中写入 `n_peaks_found`。
- 谱值统一归一化为最大值 1 后放入 `Spectrum`。
- 导向矢量网格在 `configure` 中按标称阵列一次性计算（`ArrayDescriptor.steering`），每次试验只做矩阵运算（架构第 10 章 NFR-20）。

### 13.2 空间平滑（MUSIC、Root-MUSIC、ESPRIT 共用）

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `smoothing` | `"none"` / `"forward"` / `"fb"` | `"none"` | 不平滑 / 前向空间平滑 / 前后向空间平滑 |
| `subarray` | `int \| None` | None（自动） | 子阵阵元数 L |

- 需要 `ArrayDescriptor.ula_spacing` 非 None，否则 `check` 报错。
- 自动取值 `auto_subarray(M, K, fb)`：前向平滑 L = M − K + 1；前后向平滑 L = M − ⌈K/2⌉ + 1。这一取值在保证能分辨 K 个相干信源的前提下使子阵孔径最大。
- `check` 要求：K < L ≤ M；子阵个数 M − L + 1 ≥ K（前向）或 ≥ ⌈K/2⌉（前后向）。不满足时报错并说明当前的 L 和子阵个数。
- 场景为相干信源且 `smoothing="none"` 时，`check` 给出警告。
- 平滑后的有效阵列是 L 元 ULA，后续 MUSIC 网格、Root-MUSIC 多项式阶数、ESPRIT 子阵都按 L 计算。
- 开启平滑时 `element_mask` 必须全为 True（平移不变结构要求所有阵元可用），否则 `check` 报错。

### 13.3 各算法定义

R 为样本协方差 R̂（开启平滑时为平滑后的矩阵），a(θ) 为标称导向矢量。

| 算法 id | 能力声明要点 | 参数（除公共参数外） | 定义 |
|---|---|---|---|
| `cbf` | 任意阵列；`needs_K=False`（`top_k` 模式下 K 已知时使用 K）；`coherent="yes"` | — | P(θ) = a^H R a / (a^H a)；`kind="power"` |
| `mvdr` | 任意阵列；`needs_K=False`；`coherent="no"` | `loading`（float，默认 0，对角加载比例，见 `kit.diagonal_loading`） | P(θ) = 1 / (a^H (R + δI)^{-1} a)，δ = loading·tr(R)/M；`kind="power"`。R 奇异（N < M 且 loading = 0）时 `check` 给出警告，运行时用伪逆并在 `info` 中标记 |
| `music` | 任意阵列（平滑时仅 ULA）；`needs_K=True`；`coherent="with_smoothing"` | 13.2 节平滑参数（`peak_mode` 固定为 `top_k`，不显示） | P(θ) = 1 / ‖E_n^H a(θ)‖²，E_n 为 R 的 M−K（或 L−K）个最小特征值对应的特征向量；`kind="pseudo"` |
| `root_music` | `requires_ula=True`；`supports_masked_elements=False`；`needs_K=True`；`coherent="with_smoothing"` | 13.2 节平滑参数 | C = E_n E_n^H；p(z) = Σ_k c_k z^k，系数 c_k = Σ_{j−i=k} C_ij（下标 j−i，不是 i−j；反过来会使角度反号），k = −(L−1)…(L−1)；求根后取单位圆内（\|z\| < 1）最接近单位圆的 K 个根；θ = arcsin(−∠z / (2πd))。arcsin 的自变量超出 [−1, 1] 的根丢弃；不足 K 个时返回实际个数 |
| `esprit` | `requires_ula=True`；`supports_masked_elements=False`；`needs_K=True`；`coherent="with_smoothing"` | `method`（`"ls"` / `"tls"`，默认 `"tls"`）；13.2 节平滑参数 | E_s 为 K 个最大特征值对应的特征向量，E₁、E₂ 为其前 L−1 行和后 L−1 行；LS：Ψ = E₁⁺E₂；TLS：按 Roy & Kailath 1989 的总体最小二乘解。λ_k 为 Ψ 的特征值，θ_k = arcsin(−∠λ_k / (2πd))；超出定义域的丢弃。不返回空间谱 |
| `cnn_grid`（示例学习型） | `ModelAlgorithm`；ULA，M 与模型一致；`needs_K=False`（`top_k` 模式需要 K） | `peak_mode`（`"top_k"` / `"threshold"`，默认 `"top_k"`）、`prob_threshold`（float，默认 0.5） | 输入为归一化协方差的实部、虚部两通道（`input="normalized_covariance_real_imag"`，R / ‖R‖_F）；输出为网格上的概率（sigmoid）；`top_k` 取概率谱上前 K 个局部极大值，`threshold` 取所有超过门限的局部极大值；`kind="probability"` |

**符号核对**：按 2.2 节，ULA 第 m 个元素为 z^m，z = e^{−j2πd sinθ}，所以 ∠z = −2πd sinθ，得到 θ = arcsin(−∠z / (2πd))。Root-MUSIC 的根和 ESPRIT 的特征值都用这个关系。实现时由 13.4 节的测试保证符号正确。

### 13.4 内置算法的验收测试

每个内置算法必须通过以下测试（对应需求 NFR-11 和 8.2 节），测试用例写在竞技场的 `tests/` 中：

| 测试 | 场景 | 通过条件 |
|---|---|---|
| 符号与基本正确性 | M=16，d=0.5，K=1，θ=+20°，SNR=30 dB，N=1000 | 估计值在 20° ± 0.05° 内（不是 −20°） |
| 双信源 | K=2，θ=[−10°, 10°]，SNR=20 dB，N=500，100 次 | 每次试验误差都小于：MVDR、MUSIC 为 `grid_step`；CBF 为 0.3°；Root-MUSIC、ESPRIT 为 0.05° |
| 接近 CRB | 同上，SNR 从 0 到 30 dB，500 次 | SNR ≥ 10 dB 时，Root-MUSIC 的 RMSE / sqrt(CRB) < 1.5；默认未加权 TLS-ESPRIT 的 RMSE / sqrt(CRB) < 2.0 |
| 相干信源 | K=2 相干（相位每次试验随机，即默认设置），θ=[−3°, 3°]，SNR=20 dB，N=500，1000 次，成功门限 1° | MUSIC 不平滑时成功率 < 50%；前后向平滑（子阵阵元数自动）后成功率 > 95% |
| 不同阵列 | 用测试专用的非均匀线阵插件 | CBF、MVDR、MUSIC 可运行且正确；Root-MUSIC、ESPRIT 被 `check` 拒绝 |
| 欠定 / 少快拍 | N=5 < M | 不抛出未处理异常；MVDR 给出警告 |

“双信源”和“相干信源”两条测试的场景和门限，在 2026-11-13 的设计评审中按本章公式做数值验证后修订（v0.5）：
- **双信源**：CBF 的两个波束相互影响，即使用理论协方差（没有任何随机误差），峰也在 ±9.945°，有 0.055° 的固有偏差；100 次试验中最大误差约 0.12°。这是 CBF 本身的特性，所以 CBF 的门限单独定为 0.3°，不得通过修改实现来消除这个偏差。
- **相干信源**：两个信源的间隔必须小于波束宽度（M=16、d=0.5 时半功率波束宽度约 6.3°），未平滑的 MUSIC 才会在成功率上表现为失效。原场景 ±10° 下它只是估计有偏，多数误差仍在 1° 以内，实测成功率约 90%；改为 ±3° 后实测约 11%，前后向平滑（子阵阵元数自动）后约 98%。

### 14.2 例一：传统算法（Min-Norm）

```python
# fewshot-doa/algorithms/min_norm/arena_plugin.py
import numpy as np
from arena_api import Algorithm, Capabilities, Estimate, Spectrum, ParamsModel, Param, kit

class MinNorm(Algorithm):
    id = "min_norm"
    name = "Min-Norm"
    version = "0.1.0"
    description = "最小范数法，噪声子空间中取第一个元素为 1 的最小范数向量。"
    references = ("R. Kumaresan, D. W. Tufts, 1983",)
    capabilities = Capabilities(needs_K=True, coherent="no")

    class Params(ParamsModel):
        grid_step: float = Param(0.1, gt=0, le=5, label="网格步长", unit="°")

    def configure(self, params, array, ctx):
        self.grid = np.arange(-90, 90 + params.grid_step / 2, params.grid_step)
        self.A = array.steering(self.grid)                       # (M, G)，只算一次

    def estimate(self, obs, ctx):
        _, En, _ = kit.eig_subspaces(obs.covariance(), obs.K)
        e1 = np.zeros(obs.M); e1[0] = 1
        w = En @ (En.conj().T @ e1)
        w = w / w[0]
        p = 1.0 / np.abs(w.conj() @ self.A) ** 2
        angles = kit.find_peaks_1d(self.grid, p, obs.K)
        spec = Spectrum(self.grid, p / p.max(), "pseudo") if ctx.want_spectrum else None
        return Estimate(angles, spec)
```

只需要这些。参数表单、出错隔离、计时、匹配、指标、存储、图表都由框架完成。

### 14.3 例二：学习型算法

```python
# fewshot-doa/algorithms/cnn_grid_b/arena_plugin.py
import numpy as np
from arena_api import ModelAlgorithm, Estimate, Spectrum, Param, AngleGrid, kit

class CnnGridB(ModelAlgorithm):
    id = "cnn_grid_b"
    name = "CNN 网格分类（B）"
    version = "0.1.0"

    class Params(ModelAlgorithm.Params):
        prob_threshold: float = Param(0.5, gt=0, lt=1, label="判决门限")

    def build_network(self, meta, params):
        from .net import CnnGrid                 # 同目录的 net.py，纯 PyTorch 网络定义
        return CnnGrid(M=meta.array["params"]["M"], n_grid=AngleGrid(**meta.output["grid"]).size,
                       **meta.hparams)

    def preprocess(self, obs_list, meta, params):
        import torch
        R = np.stack([o.covariance() for o in obs_list])               # (B, M, M)
        R = R / np.linalg.norm(R, axis=(1, 2), keepdims=True)
        return torch.from_numpy(np.stack([R.real, R.imag], axis=1)).float()  # (B, 2, M, M)

    def postprocess(self, output, obs_list, meta, params, want_spectrum):
        grid = AngleGrid(**meta.output["grid"])
        prob = output.sigmoid().cpu().numpy()                          # (B, G)
        results = []
        for o, p in zip(obs_list, prob):
            angles = kit.find_peaks_1d(grid.points, p, o.K, refine=False)  # 默认 needs_K=True，K 一定存在
            angles = angles[p[grid.index_of(angles)] >= params.prob_threshold]   # 去掉低于门限的峰
            spec = Spectrum(grid.points, p, "probability") if want_spectrum else None
            results.append(Estimate(angles, spec))
        return results
```

模型包（权重 + `model.json`）由训练脚本调用 `arena.models.export` 生成（架构 9.6 节），导入工作目录的 `models/` 后，在参数表单的“模型包”中选择即可。

### 14.5 一致性检查（arena plugin check）

| 检查项 | 内容 |
|---|---|
| 定义 | 必需的类属性；`id` 格式；`Params` 字段类型（5.3 节）；JSON Schema 可导出 |
| 默认参数可运行 | 用默认参数在标准场景（M=16 ULA，K=2，θ=[−10°, 10°]，SNR=20 dB，N=200）上运行 20 次，无异常 |
| 输出格式 | 每次输出都满足 6.4 节规则 |
| 合理性 | 上述场景中成功率 > 50%（只给警告，不判失败，因为有些算法本来就不适合这个场景） |
| 确定性 | 同一种子运行两次，结果逐位相同（GPU 推理允许 1e-5 以内的差异） |
| 批量一致 | 声明 `batch=True` 时，`estimate_batch` 与逐次 `estimate` 结果一致（同上容差） |
| 不修改输入 | 运行后 `obs.X` 未被修改 |
| 资源释放 | `close()` 可重复调用；学习型算法 `close()` 后显存回到加载前水平（± 50 MB） |
| 无全局随机状态 | 运行前后 `np.random` 全局状态不变 |

### 14.6 作者自查清单

- [ ] `id` 是小写字母、数字、下划线，以后不再修改
- [ ] 所有角度用度，`angles` 是一维数组 `(K̂,)`
- [ ] 自己构造导向矢量时符号为 `exp(-j·2π·p·u)`，或直接用 `array.steering()`
- [ ] 没有修改 `obs.X`
- [ ] 随机数只用 `ctx.rng`，试验之间不保留影响结果的状态
- [ ] 耗时的预计算放在 `configure` 中，模型加载放在 `load` 中
- [ ] 没有在 `estimate` 中捕获全部异常再返回空结果
- [ ] 模块顶层没有 import torch（学习型算法在方法内部 import）
- [ ] `arena plugin check <id>` 通过
